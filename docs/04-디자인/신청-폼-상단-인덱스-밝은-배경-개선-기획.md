# 신청폼 왼쪽 스프링·상단 포스트잇 인덱스·밝은 배경 개선 기획

- 작성일: 2026-09-01
- 상태: 구현 및 반응형 검수 완료
- 구현·검수일: 2026-09-01
- 적용 대상: 데이로그 LIFE NOTE 신청폼 전체 화면
- 선행 기준: [신청폼 UI 피드백 반영 디자인 수정 명세](신청-폼-UI-피드백-반영-명세.md)

## 1. 기획 배경

현재 신청폼은 어두운 책상 배경 위에서 상단 스프링과 포스트잇 내비게이터를 함께 사용합니다. 노트의 물성은 분명하지만, 스프링과 인덱스가 모두 상단에 놓이면 같은 공간에서 경쟁하고 포스트잇이 노트와 분리된 별도 메뉴처럼 보일 수 있습니다.

또한 어두운 배경과 입체적인 제본·종이 그림자·포스트잇이 동시에 강조되면서 신청 내용보다 외곽 장식이 먼저 보일 수 있습니다.

이번 개선에서는 스프링을 노트 왼쪽 가장자리로 옮기고, 포스트잇을 노트 상단 가장자리에 실제로 끼워둔 **페이지 인덱스**로 재정의합니다. 전체 배경도 밝게 바꿔 질문과 입력에 집중할 수 있는 화면을 만듭니다.

## 2. 핵심 결정

1. 포스트잇은 장식이 아니라 특정 페이지를 표시하고 이동하는 인덱스입니다.
2. 스프링은 노트 왼쪽 바깥에 세로로 배치해 상단 인덱스와 역할 및 공간을 분리합니다.
3. 인덱스는 오른쪽 세로 배치가 아니라 노트 상단의 가로 배치를 사용합니다.
4. 인덱스의 아래쪽 6~8px은 노트 종이 뒤에 가려 실제로 끼워둔 것처럼 보이게 합니다.
5. 전체 배경은 순백색이 아닌 밝은 회백색 `#F6F7F5`를 사용합니다.
6. 노트 종이는 기존 Warm Ivory `#FFF9EF`를 유지해 배경과 구분합니다.
7. 데스크톱과 모바일에서 `왼쪽 스프링 + 상단 인덱스` 원칙을 유지합니다.
8. 질문 순서, 잠금 조건과 페이지 이동 로직은 변경하지 않습니다.

## 3. 목표 경험

사용자는 상단 인덱스를 보고 다음 내용을 즉시 이해해야 합니다.

- 현재 어느 페이지를 작성하고 있는지
- 이전에 작성한 페이지로 돌아갈 수 있는지
- 아직 열리지 않은 페이지가 무엇인지
- 노트가 Page 00부터 Page 06까지 이어지는 하나의 신청 과정이라는 점

내비게이터는 웹사이트의 메뉴 바보다 실제 노트에 붙인 견출지처럼 보여야 합니다. 다만 장식 때문에 글자가 작아지거나 조작 범위가 줄어들어서는 안 됩니다.

## 4. As-Is와 To-Be

| 구분 | As-Is | To-Be |
| --- | --- | --- |
| 전체 배경 | 어두운 네이비 책상 그라디언트 | 밝은 회백색 단색 배경 |
| 스프링 위치 | 노트 상단의 가로 제본 | 노트 왼쪽 바깥의 세로 제본 |
| 내비게이터 위치 | 노트 위에 분리된 가로 행 | 노트 상단 가장자리에 일부가 끼워진 가로 인덱스 |
| 내비게이터 의미 | 페이지 목록 또는 메뉴 | 표시해둔 노트 페이지로 이동하는 견출지 |
| 현재 페이지 | 분홍색과 위로 들린 포스트잇 | 분홍색, 4px 돌출, Deep Navy 테두리의 현재 인덱스 |
| 노트 외곽 | 강한 다층 그림자 | 밝은 배경에서 경계만 보이는 얕은 그림자 |
| 헤더 | 흰색 계열 글자와 어두운 배경 | Deep Navy 글자와 밝은 배경 |
| 모바일 | 상단 행에 모든 탭 압축 | 노트 상단에서 가로 스크롤, 현재 인덱스 자동 노출 |

## 5. 화면 구조

```text
DAYLOG / LIFE NOTE                         나만의 하루 설계

          [표지] [01 리듬] [02 온도] [03 지속] [04 습관] …
          └────── 포스트잇 아래쪽이 종이 뒤에 6~8px 가려짐
      ┌────────────────────────────────────────────────┐
   ○  │  붉은선   질문 제목                            │
   ○  │           질문 설명                            │
   ○  │                                                │
   ○  │           선택 또는 입력 콘텐츠               │
   ○  │                                                │
   ○  │           이전                   다음          │
      └────────────────────────────────────────────────┘
      ↑
   왼쪽 세로 스프링
```

### 구조 원칙

- 스프링은 노트 왼쪽 바깥에 세로로 붙이고 포스트잇 인덱스는 종이 상단에 가로로 붙입니다.
- 상단 인덱스의 왼쪽 시작점은 스프링 폭을 제외한 실제 종이의 왼쪽 정렬축과 맞춥니다.
- 인덱스는 `.spiral-notebook-container` 안에 두되 `.spiral-page-sheet` 밖에 둡니다.
- 노트 종이가 포스트잇 아래쪽 6~8px을 덮도록 레이어 순서를 설정합니다.
- 인덱스를 위한 상단 공간은 레이아웃에 포함해 헤더나 노트와 겹치지 않게 합니다.
- 노트 본문 패딩과 붉은 세로선 위치는 기존 확정값을 유지합니다.
- 왼쪽에서 `스프링 → 붉은 세로선 → 콘텐츠` 순서가 명확하게 보이게 합니다.

## 6. 밝은 배경 디자인

### 컬러 구성

| 역할 | 컬러 | HEX | 적용 |
| --- | --- | --- | --- |
| 화면 배경 | Soft White Gray | `#F6F7F5` | 전체 브라우저 배경 |
| 노트 종이 | Warm Ivory | `#FFF9EF` | 노트 본문 |
| 입력·선택 카드 | Clean White | `#FFFFFF` | 카드와 입력 면 |
| 노트 외곽선 | Soft Beige | `#EDE1CF` | 종이 경계와 구분선 |
| 주요 글자·제본 | Deep Navy | `#172033` | 헤더, 제목, 스프링 바 |
| 이동 가능 인덱스 | Post-it Yellow | `#F7E5A1` | 방문했거나 이동 가능한 페이지 |
| 현재 인덱스 | Active Pink | `#FF8FB1` | 현재 페이지 |
| 잠긴 인덱스 | Soft Beige | `#EDE1CF` | 아직 이동할 수 없는 페이지 |

### 순백색 대신 회백색을 쓰는 이유

- `#FFFFFF` 배경에서는 흰색 카드와 노트 외곽이 쉽게 사라집니다.
- `#F6F7F5`는 밝은 인상을 유지하면서 Warm Ivory 노트와 Clean White 카드를 구분합니다.
- 컬러 인덱스가 선명하게 보이지만 화면 전체가 이벤트 페이지처럼 화려해지지 않습니다.

### 외곽 표현

- 기존 어두운 방사형 책상 그라디언트는 제거합니다.
- 종이 스택은 1~2장만 보이도록 단순화합니다.
- 노트 그림자는 `0 18px 44px rgb(23 32 51 / 12%)` 수준으로 낮춥니다.
- 왼쪽 스프링 제본은 Deep Navy를 유지하되 검은색에 가까운 강한 대비는 완화합니다.
- 노트 가로줄과 붉은 세로선은 기존 농도를 유지하거나 밝은 배경 검수 후 10~15% 범위에서만 조정합니다.

## 7. 상단 포스트잇 인덱스

### 배치

- 왼쪽 스프링과 겹치지 않도록 실제 종이 면의 상단 가장자리에 한 줄로 배치합니다.
- 포스트잇의 보이는 높이는 36~40px, 버튼 터치 영역은 최소 44px입니다.
- 포스트잇 아래쪽 6~8px을 노트 종이 뒤로 숨깁니다.
- 포스트잇 간 간격은 6~8px을 사용합니다.
- 회전은 `-1deg`에서 `1deg` 이내로 제한합니다.
- 오른쪽 세로 인덱스는 사용하지 않습니다.

## 8. 왼쪽 스프링 제본

### 데스크톱·태블릿

- 스프링 영역은 노트 종이 왼쪽 바깥에 세로로 배치합니다.
- 제본 레일 너비는 36~40px을 기준으로 합니다.
- 링은 위에서 아래로 일정한 간격으로 반복하고 12~14개 안에서 화면 높이에 맞춰 조정합니다.
- 종이 구멍과 금속 링은 기존 입체 표현을 유지하되 그림자 농도를 낮춥니다.
- 스프링 영역은 실제 콘텐츠 너비에 포함하지 않습니다.

### 모바일

- 480px 이하에서는 스프링 영역을 20~24px로 줄입니다.
- 링의 개수보다 일정한 간격과 연속성이 먼저 보이게 합니다.
- 종이 구멍과 링 크기를 함께 줄여 본문 폭을 과도하게 차지하지 않게 합니다.
- 320px에서도 붉은 세로선과 콘텐츠 사이 최소 14px 간격을 유지합니다.

### 왼쪽 영역 정렬 순서

```text
화면 여백 → 스프링 20~40px → 종이 여백 → 붉은 세로선 → 14px 이상 → 콘텐츠
```

스프링과 붉은 세로선이 동시에 강하게 보이지 않도록 붉은 선은 현재의 낮은 채도를 유지합니다.

## 9. 인덱스 라벨과 상태

### 라벨

| 페이지 | 라벨 |
| --- | --- |
| Page 00 | 표지 |
| Page 01 | 01 리듬 |
| Page 02 | 02 온도 |
| Page 03 | 03 지속 |
| Page 04 | 04 습관 |
| Page 05 | 05 안내 |
| Page 06 | 06 신청 |

라벨은 현재 구현과 동일하게 유지합니다. 모바일에서도 페이지 의미를 알 수 있도록 숫자만 표시하지 않습니다.

### 상태

| 상태 | 시각 표현 | 동작 |
| --- | --- | --- |
| 현재 | 분홍색, 2px Deep Navy 테두리, 4px 위로 돌출, 굵은 글자 | `aria-current="page"`, 클릭해도 현재 상태 유지 |
| 이동 가능 | 연한 노란색, 1px 반투명 테두리, 얕은 그림자 | 해당 페이지로 즉시 이동 |
| 잠김 | 베이지색, 약한 그림자, 채도 감소 | `disabled`, 이동하지 않음 |
| Hover | 1~2px 들림 | 상태색 유지 |
| Focus | 3px Deep Navy 외곽선과 3px 간격 | 키보드 포커스 표시 |

현재 상태는 색 외에도 위치, 테두리, 글자 굵기와 `aria-current`로 구분합니다.

## 10. 페이지 이동 동작

- 사용자가 이동 가능한 인덱스를 누르면 해당 페이지로 즉시 전환합니다.
- 기존에 작성한 답변은 유지합니다.
- 잠긴 페이지를 건너뛰어 이동할 수 없습니다.
- 뒤 페이지에서 이전 질문으로 돌아간 후 답을 수정하면 저장 데이터에 반영합니다.
- 페이지 전환 후 질문 제목으로 포커스를 이동합니다.
- 현재 인덱스가 가로 영역 밖에 있으면 `scrollIntoView({ inline: "center" })`로 자동 노출합니다.
- 페이지 전환 모션은 기존 240ms 이내의 짧은 페이드·수직 이동을 유지합니다.
- 모션 감소 환경에서는 즉시 전환합니다.

## 11. 반응형 기준

### 769px 이상

- 7개 인덱스를 노트 상단에 한 줄로 표시합니다.
- 왼쪽 스프링은 36~40px, 상단 인덱스는 스프링을 제외한 종이 너비를 기준으로 배치합니다.
- 가로 공간이 충분하면 스크롤바 없이 모두 노출합니다.

### 481~768px

- 상단 가로 배치를 유지합니다.
- 왼쪽 스프링 폭을 28~32px로 줄입니다.
- 탭의 좌우 패딩을 줄이되 44px 터치 높이는 유지합니다.
- 필요한 경우 인덱스 영역만 가로 스크롤합니다.

### 480px 이하

- 상단 가로 배치를 그대로 유지합니다.
- 왼쪽 스프링 폭을 20~24px로 줄입니다.
- `표지`, `01 리듬` 등 전체 라벨을 보존합니다.
- 스크롤바는 숨기되 터치 스와이프와 키보드 탐색을 허용합니다.
- 현재 인덱스를 자동으로 중앙에 가깝게 노출합니다.
- 인덱스 스크롤이 전체 페이지의 가로 넘침을 만들면 안 됩니다.

## 12. 헤더 수정

밝은 배경에 맞춰 상단 헤더의 컬러와 간격을 조정하고 일반 문서 흐름 안에 배치합니다.

- `DAYLOG`: Deep Navy
- `/ LIFE NOTE`: Ink Secondary `#4A5568`
- `나만의 하루 설계` 배지: Clean White 또는 Warm Ivory 면, Soft Beige 테두리
- 배지 안의 점: Growth Yellow
- 헤더와 노트 사이 간격은 포스트잇 인덱스 높이를 포함해 최소 20px 확보
- 헤더 패딩은 `8px 12px`으로 4px 간격 체계를 따름

### 4px 간격 체계

- `padding`, `margin`, `gap`의 px 값은 원칙적으로 4의 배수를 사용합니다.
- 세부 컴포넌트는 `4·8·12·16·20·24px` 순서로 밀도를 조정합니다.
- 테두리, 물리적 기울기·겹침, 아이콘 크기와 접근성용 화면 숨김 값은 간격 체계 적용 대상에서 제외합니다.

## 13. 구현 영향

### 구조 변경

현재 내비게이터는 노트 컨테이너 밖에 있습니다. 구현 시 다음 구조로 이동합니다.

```text
.desk-canvas
  .desk-header
  .spiral-notebook-container
    .spiral-nav-tabs
    .spiral-binding-bar
    .spiral-page-sheet
```

- `navTabs`, 잠금 조건, `isTabActive()`와 클릭 로직은 그대로 사용합니다.
- `.spiral-nav-tabs`의 JSX 위치만 `.spiral-notebook-container` 내부로 이동합니다.
- 내비게이터를 `.spiral-page-sheet` 안에 넣지 않습니다. 종이의 `overflow: hidden` 때문에 포스트잇이 잘릴 수 있습니다.
- `.spiral-binding-bar`는 상단 막대가 아니라 컨테이너 왼쪽의 세로 레일로 재배치합니다.
- `.spiral-binding-inner`는 링을 위아래로 배열하도록 `flex-direction: column`을 사용합니다.
- `.spiral-page-sheet`는 스프링 폭만큼 오른쪽으로 이동하되 전체 화면의 가로 넘침을 만들지 않습니다.

### 주요 선택자

| 대상 | 선택자 | 변경 내용 |
| --- | --- | --- |
| 전체 배경 | `.desk-canvas` | 네이비 그라디언트에서 `#F6F7F5`로 변경 |
| 헤더 | `.desk-header`, `.desk-brand-*`, `.desk-session-tag` | 밝은 배경용 텍스트·면 컬러 적용 |
| 노트 컨테이너 | `.spiral-notebook-container` | 왼쪽 스프링과 상단 인덱스의 레이어 기준 설정 |
| 내비게이터 | `.spiral-nav-tabs` | 노트 내부 이동, 종이 상단과 6~8px 겹침 |
| 인덱스 | `.spiral-nav-tab` | 기존 상태 컬러 유지, 부착 위치 중심으로 조정 |
| 제본 | `.spiral-binding-bar` | 왼쪽 세로 레일로 전환 |
| 링 배열 | `.spiral-binding-inner` | 가로 배열에서 세로 배열로 전환 |
| 종이 | `.spiral-page-sheet` | 밝은 배경용 그림자 단순화 |
| 붉은 선 | `.notebook-red-margin` | 스프링 안쪽에서 기존 본문 간격 유지 |

## 14. 접근성

- 내비게이터는 의미가 있는 `nav`와 실제 `button` 구조를 유지합니다.
- 현재 페이지에는 `aria-current="page"`를 적용합니다.
- 잠긴 페이지에는 실제 `disabled` 속성을 적용합니다.
- 모든 탭은 최소 44×44px 조작 영역을 유지합니다.
- 분홍색과 노란색 위에는 Deep Navy 텍스트를 사용합니다.
- 가로 스크롤 영역에서도 키보드 포커스가 가려지지 않아야 합니다.
- 배경이 밝아져도 헤더, 노트 외곽선과 비활성 상태의 명도 대비를 확인합니다.

## 15. 검수 기준

- [x] 전체 배경이 밝은 회백색이며 노트와 흰색 카드가 서로 구분된다.
- [x] 스프링은 노트 왼쪽 바깥에 세로로 배치되고 상단 인덱스와 겹치지 않는다.
- [x] 포스트잇 인덱스가 노트와 분리된 메뉴가 아니라 상단에 끼워진 견출지처럼 보인다.
- [x] 인덱스 아래쪽 6~8px이 노트 종이 뒤에 자연스럽게 가려진다.
- [x] Page 00~06 라벨과 순서가 현재 흐름과 일치한다.
- [x] 현재, 이동 가능, 잠김과 포커스 상태가 색 외의 표현으로도 구분된다.
- [x] 탭 클릭 시 해당 페이지로 이동하고 기존 답변이 유지된다.
- [x] 잠긴 페이지는 클릭하거나 키보드로 실행할 수 없다.
- [x] 페이지 전환 후 질문 제목에 포커스가 이동한다.
- [x] 1280px에서 7개 인덱스가 한 줄로 자연스럽게 보인다.
- [x] 768px, 375px와 320px에서 인덱스 영역만 가로 스크롤된다.
- [x] 320px에서 왼쪽 스프링, 붉은 선과 콘텐츠가 겹치지 않는다.
- [x] 콘텐츠는 모든 너비에서 붉은 선보다 최소 14px 오른쪽에 있다.
- [x] 모바일에서 현재 인덱스가 자동으로 보이는 위치로 이동한다.
- [x] 전체 페이지에 가로 넘침이 발생하지 않는다.

### 구현 검수 결과

- 1280×720, 768×900, 375×812와 320×700에서 실제 렌더링을 확인했습니다.
- 데스크톱에서는 7개 인덱스가 한 줄 안에 표시되고, 모바일에서는 인덱스 영역만 가로 스크롤됩니다.
- 스프링 폭은 데스크톱 38px, 태블릿 30px, 모바일 22px로 적용했습니다.
- 종이 기준 붉은 선과 콘텐츠 시작점은 데스크톱 `49px / 73px`, 태블릿 `29px / 49px`, 375px `19px / 33px`, 320px `15px / 29px`로 확인했습니다.
- 질문 이동, 잠금 해제, 제목 포커스, 현재 인덱스 자동 노출과 이전 답변 보존을 확인했습니다.
- 접근성용 `.sr-only`의 `margin: -1px`을 제외한 모든 px 기반 `padding`, `margin`, `gap`을 4의 배수로 정리했습니다.
- 빌드, 린트와 7개 계약 테스트를 통과했습니다.
- [x] 밝은 배경에서 노트 그림자가 과도하게 진하지 않다.
- [x] `prefers-reduced-motion`에서 불필요한 이동 애니메이션이 제거된다.
