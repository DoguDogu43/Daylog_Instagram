# 신청폼 카드 기반 라이트 리디자인 기획

- 작성일: 2026-09-03
- 상태: 1차 구현 및 브라우저 검수 완료
- 구현·검수일: 2026-09-03
- 적용 대상: 데이로그 LIFE NOTE 신청폼 Page 00~06 및 완료 화면
- 참고 범위: 2026-09-03 대화에 첨부된 카드 기반 라이트 UI 이미지

## 1. 문서 목적

이 문서는 현재 신청폼의 질문·데이터·제출 구조를 유지하면서, 화면을 밝고 정돈된 카드 기반 인터페이스로 개편하기 위한 디자인 방향과 구현 판단 기준을 정의합니다.

이번 개편의 핵심은 LIFE NOTE라는 경험명을 없애는 것이 아니라, 스프링·종이줄·포스트잇 같은 물리적 노트 표현에서 벗어나 **질문, 선택, 진행 상태와 다음 행동**이 먼저 보이게 만드는 것입니다.

이 문서는 2026-09-03 사용자 승인에 따라 구현된 현재 신청폼의 시각 기준입니다. 기존 [신청 경험 디자인](신청-폼-디자인.md), [UI 피드백 반영 명세](신청-폼-UI-피드백-반영-명세.md), [밝은 배경 개선 기획](신청-폼-상단-인덱스-밝은-배경-개선-기획.md)의 노트 형태 관련 기준보다 우선합니다. 질문, 데이터와 제출 규격은 기존 구현 명세를 유지합니다.

## 2. 참고 이미지 해석 원칙

첨부 이미지는 디자인 분위기와 구성 원칙을 참고하기 위한 자료입니다. 이미지 안의 문구, 영문 설명, 기기 프레임과 장식 그래픽은 사용자 요구사항이나 구현 지시로 간주하지 않습니다.

### 채택하는 요소

- 밝은 회백색 배경과 넓은 여백
- 모바일에서 한눈에 읽히는 중앙 단일 열
- 제목, 설명, 정보 카드를 분리한 명확한 위계
- Clean White 카드와 얕은 그림자
- 2~3개의 색만 강조에 사용하는 절제된 컬러
- 선택지를 빠르게 비교할 수 있는 정돈된 그리드
- 화면 하단에서 쉽게 찾을 수 있는 주 행동 버튼
- 브랜드 의미를 압축한 단순 기하 그래픽

### 그대로 사용하지 않는 요소

- 실제 서비스 화면을 검은색 스마트폰 프레임 안에 가두는 표현
- 목재 책상, 노트와 펜을 배경으로 사용하는 홍보용 목업
- 의미 없는 플로차트 장식
- 참고 이미지 속 문구와 질문 구성
- 데이로그 컬러 체계와 다른 임의의 청록색을 주 브랜드색으로 추가하는 방식
- 자동 생성 이미지의 흐릿한 글자나 비정상적인 한글 형태

### 해석 결론

참고 이미지의 형태를 복제하지 않고 다음 한 문장으로 번역합니다.

> 밝은 화면 위에 질문과 선택을 카드로 정돈하고, 사용자가 현재 할 일과 다음 행동을 즉시 이해하게 한다.

## 3. 리디자인 목표

1. 첫 화면에서 서비스 목적, 질문 수, 예상 시간과 다음 행동을 5초 안에 이해하게 합니다.
2. 한 화면에서 질문 하나와 주 행동 하나만 강하게 보이게 합니다.
3. 노트 형태와 장식을 제거해 선택 카드, 입력 필드와 오류 메시지의 가독성을 높입니다.
4. 모바일 웹을 기준으로 설계하되 태블릿과 PC에서는 빈 공간만 늘어나지 않게 합니다.
5. 기존 브랜드의 따뜻함과 신뢰감을 유지하면서 더 가볍고 프리미엄한 인상을 만듭니다.
6. 질문 순서, 입력 데이터, 검증과 제출 API를 변경하지 않고도 1차 구현할 수 있게 합니다.

## 4. 확정 디자인 결정

### 콘셉트명

**DAYLOG LIFE NOTE · Card-Based Clean Interface**

### 노트 형태 제거

2026-09-03 사용자 결정에 따라 실제 노트처럼 보이는 형태에서 완전히 벗어납니다.

- 스프링 제본을 제거합니다.
- 종이 가로줄과 붉은 세로 여백선을 제거합니다.
- 포스트잇 페이지 인덱스를 제거합니다.
- 종이가 겹친 스택과 종이 모서리 장식을 제거합니다.
- 종이 넘김 모션과 손글씨·다이어리 꾸미기 표현을 사용하지 않습니다.
- `LIFE NOTE`는 제품의 경험명과 브랜드 카피로만 유지합니다.

### 핵심 방향

- LIFE NOTE는 `내 하루를 짧게 정리하는 경험`으로 표현합니다.
- 화면은 `헤더 → 진행 정보 → 질문 또는 안내 카드 → 하단 행동 영역`의 일관된 구조를 사용합니다.
- 사용자가 선택한 내용은 카드의 테두리, 체크 아이콘, 배경 변화와 텍스트로 동시에 표시합니다.
- 장식보다 정렬, 여백, 글자 크기와 대비로 브랜드 완성도를 만듭니다.

### 유지하는 것

- `DAYLOG / LIFE NOTE` 명칭
- 4개의 생활 질문
- LIFE SESSION 안내 후 신청 정보를 받는 흐름
- 기존 질문과 신청 데이터 스키마
- 이전 단계로 돌아가 답변을 수정하는 기능
- Growth Yellow, Deep Navy, Warm Ivory, Sage Green의 기존 의미
- 완료 상태의 Sage Green 사용
- 시스템 산세리프 기반의 읽기 쉬운 한글

### 변경 요약

| 구분 | 이전 구현 | 현재 구현 |
| --- | --- | --- |
| 중심 표현 | 실제 스프링 노트 | 정돈된 디지털 LIFE NOTE |
| 화면 외곽 | 종이, 제본과 포스트잇 | 밝은 캔버스와 중앙 앱 패널 |
| 페이지 이동 | 상단 포스트잇 인덱스 | 얇은 진행 표시와 이전 버튼 |
| 선택 영역 | 종이 조각형 카드 | 균일한 흰색 카드 그리드 |
| 강조 방식 | 분홍 형광펜, 노란 메모 | 굵기, 체크, 테두리와 제한된 색면 |
| CTA | 페이지별 종이 버튼 | 화면 하단의 일관된 행동 바 |
| 장식 | 가로줄, 붉은 선, 링 | 작은 기하 패턴 또는 선형 아이콘 |
| 데스크톱 | 큰 노트 한 권 | 중앙 집중형 패널과 넉넉한 여백 |

## 5. 전체 화면 구조

```text
┌──────────────────────────────────────────────┐
│ DAYLOG / LIFE NOTE                 단계 표시 │
│                                              │
│                작은 상태 라벨               │
│              질문 또는 안내 제목            │
│                  짧은 설명                   │
│                                              │
│       ┌──────────────────────────────┐       │
│       │ 질문·안내·입력 카드          │       │
│       └──────────────────────────────┘       │
│                                              │
│       ┌──────────────────────────────┐       │
│       │ 이전                다음 CTA │       │
│       └──────────────────────────────┘       │
└──────────────────────────────────────────────┘
```

### 앱 셸

- 전체 캔버스는 Soft White Gray `#F6F7F5`를 유지합니다.
- 핵심 콘텐츠는 모바일 `100%`, 데스크톱 최대 `560px`의 중앙 단일 열을 기본으로 합니다.
- 신청 정보처럼 입력량이 많은 화면만 최대 `720px`까지 확장할 수 있습니다.
- 데스크톱에서도 스마트폰 베젤을 그리지 않습니다.
- 앱 패널과 배경의 경계는 테두리보다 여백과 아주 얕은 그림자로 구분합니다.
- 높이가 충분한 첫 화면에서는 중앙 정렬을 사용할 수 있지만, 질문과 입력 화면은 자연스러운 세로 스크롤을 우선합니다.

### 공통 헤더

- 왼쪽에는 `DAYLOG / LIFE NOTE`를 한 줄로 배치합니다.
- 오른쪽에는 현재 위치를 `1 / 4`, `안내`, `신청`처럼 짧게 표시합니다.
- 헤더 높이는 모바일 `52~56px`, 태블릿 이상 `60~64px`를 기준으로 합니다.
- 헤더는 콘텐츠를 가리지 않는 일반 문서 흐름에 둡니다.
- 질문 화면에서만 얇은 진행 막대를 헤더 아래에 표시합니다.

### 진행 표시

- Page 01~04는 `1 / 4` 형식의 텍스트와 4칸 세그먼트 막대를 함께 사용합니다.
- 완료한 칸은 Deep Navy, 현재 칸은 Growth Yellow, 남은 칸은 Soft Beige로 표시합니다.
- 색 외에도 `현재 2번째 질문, 전체 4개`와 같은 접근성 이름을 제공합니다.
- Page 05와 06은 질문 진행률에서 분리해 각각 `프로그램 안내`, `신청 정보`로 표시합니다.
- 이전 단계로 돌아가는 버튼은 헤더 또는 하단 행동 바에서 항상 찾을 수 있게 합니다.

## 6. 컬러 사용

기존 브랜드 팔레트를 유지하고 참고 이미지의 청록색을 새 주 브랜드색으로 추가하지 않습니다.

| 역할 | 토큰 | 적용 |
| --- | --- | --- |
| 전체 배경 | Soft White Gray `#F6F7F5` | 브라우저 캔버스 |
| 기본 카드 | Clean White `#FFFFFF` | 소개, 선택, 입력과 안내 카드 |
| 따뜻한 보조면 | Warm Ivory `#FFF9EF` | 소개 카드, 개인정보 안내 |
| 주요 텍스트 | Deep Navy `#172033` | 제목, 아이콘과 핵심 정보 |
| 본문 | Charcoal `#252525` | 설명과 입력 텍스트 |
| 주 행동 | Growth Yellow `#F5B82E` | 다음, 시작과 제출 CTA |
| 완료 | Sage Green `#879A7B` | 완료 아이콘, 완료 화면 패턴 |
| 비활성 면 | Soft Beige `#EDE1CF` | 진행 전 상태와 구분선 |

### 컬러 원칙

- 한 화면의 강한 색면은 원칙적으로 CTA와 선택 상태를 합쳐 2곳 이내로 제한합니다.
- Growth Yellow 위에는 Deep Navy 텍스트를 사용합니다.
- Sage Green은 기존 기준대로 완료와 변화가 쌓인 상태에만 사용합니다.
- 분홍색 포스트잇과 형광펜은 제거합니다.
- 카드 간 구분은 여러 색보다 여백, 테두리와 그림자를 먼저 사용합니다.

## 7. 타이포그래피와 간격

### 타입 위계

| 용도 | 모바일 | 태블릿·PC | 굵기 | 행간 |
| --- | ---: | ---: | ---: | ---: |
| 화면 제목 | `28~32px` | `32~36px` | 700 | 1.25 |
| 질문 제목 | `26~30px` | `30~34px` | 700 | 1.3 |
| 카드 제목 | `16~18px` | `17~19px` | 600~700 | 1.4 |

- 한글 제목에는 과한 자간 축소를 사용하지 않습니다.
- 중앙 정렬은 첫 화면과 완료 화면에만 사용하고, 질문·입력·안내 정보는 왼쪽 정렬을 기본으로 합니다.
- 제목 폭은 모바일에서 12~16자 정도가 한 줄에 보이는 범위로 제한합니다.

### 간격 체계

- 4px 세부 단위와 8px 기본 단위를 유지합니다.
- 화면 좌우 여백은 모바일 `20px`, 360px 이하 `16px`, 태블릿 이상 `24~32px`를 사용합니다.
- 헤더와 제목은 `32~40px`, 제목과 설명은 `12px`, 설명과 첫 카드는 `24px` 간격을 기준으로 합니다.
- 카드 간격은 `12px`, 카드 내부 여백은 `16~20px`를 사용합니다.
- CTA 위에는 최소 `24px`의 숨 쉴 공간을 둡니다.

## 8. 카드 시스템

### 공통 카드

- 배경: Clean White
- 테두리: Deep Navy 10~14% 또는 Soft Beige 1px
- 모서리: `14~16px`
- 그림자: `0 8px 24px rgb(23 32 51 / 8%)`
- 내부 여백: 모바일 `16px`, 태블릿 이상 `20px`
- 카드 자체를 기울이거나 서로 겹치지 않습니다.

### 정보 카드

- 아이콘, 짧은 수치 또는 핵심 문구, 한 줄 설명 순서로 구성합니다.
- 첫 화면에서는 `4개 질문`, `약 3분`, `대면 체험 신청` 3개를 사용합니다.
- 모바일 `3열`을 우선하되 320px 또는 텍스트 확대 환경에서는 `1열` 또는 `2+1열`로 자연스럽게 바뀝니다.
- 아이콘은 20~24px의 동일한 선 굵기를 사용합니다.

### 선택 카드

- 일반 질문은 모바일 1열을 기본으로 합니다.
- 선택지가 짧은 생활 영역은 모바일 2열, 360px 이하 1열을 허용합니다.
- 카드 전체를 실제 `label`로 사용하고 최소 높이 `64px`, 터치 영역 `44×44px` 이상을 보장합니다.
- 선택 전에는 1px 테두리와 빈 라디오·체크를 표시합니다.
- 선택 후에는 2px Deep Navy 테두리, 옅은 Growth Yellow 면과 체크 아이콘을 표시합니다.
- 순위 선택은 체크 대신 `1`, `2`, `3` 배지를 표시합니다.
- Hover는 1px 상승과 그림자 변화까지만 사용합니다.

### 입력 카드

- 질문 설명과 입력 필드를 한 카드 안에 묶습니다.
- 입력 배경은 완전 불투명한 흰색을 유지합니다.
- 레이블, 도움말, 입력, 글자 수와 오류의 읽기 순서를 고정합니다.
- 빠른 입력 예시는 pill 칩으로 제공하되 사용자가 쓴 값과 혼동되지 않게 보조 스타일을 사용합니다.

## 9. 하단 행동 영역

- 주 행동은 화면 하단에서 쉽게 찾을 수 있는 가로 전체 버튼으로 제공합니다.
- 모바일에서는 viewport 높이가 충분할 때만 `position: sticky`를 사용합니다.
- 하단 영역은 반투명 배경 대신 캔버스와 같은 불투명 면을 사용해 아래 콘텐츠가 비치지 않게 합니다.
- `env(safe-area-inset-bottom)`을 포함합니다.
- 화면 높이 `640px` 미만 또는 가상 키보드가 열린 상태에서는 일반 문서 흐름으로 전환할 수 있습니다.
- 이전 행동은 텍스트 버튼, 다음·시작·제출은 채워진 버튼으로 위계를 구분합니다.
- 비활성 버튼은 `opacity`만 낮추지 않고 배경, 테두리와 문구를 함께 변경합니다.

## 10. 화면별 디자인

### Page 00. 시작 화면

구성 순서:

1. `나만의 하루 설계` 작은 상태 라벨
2. `내 생활에 맞는 습관을 함께 찾아봐요` 대표 제목
3. 서비스 목적을 설명하는 짧은 Warm Ivory 소개 카드
4. `4개 질문 · 약 3분 · 대면 체험 신청` 정보 카드 3개
5. `내 하루 기록 시작하기` 전체 너비 CTA

원칙:

- 첫 화면에는 입력이나 선택지를 두지 않습니다.
- 제목은 최대 3줄, 설명은 최대 3줄 안에서 읽히게 합니다.
- 대표 이미지 대신 작은 선형 아이콘 또는 단순 기하 패턴을 사용할 수 있습니다.
- 기하 패턴은 CSS 또는 접근성에서 숨긴 SVG로 구현하고 의미 있는 텍스트를 대신하지 않습니다.

### Page 01. 오늘의 리듬

- 질문 제목과 한 줄 설명 뒤에 선택 카드를 1열로 표시합니다.
- 카드 문장이 짧아도 억지로 2열로 만들지 않습니다.
- 선택 즉시 상태를 보여주되 다음 단계 이동은 사용자가 CTA를 눌러 확정합니다.

### Page 02. 편안한 순간과 버거운 순간

- 두 입력 카드를 위아래로 배치합니다.
- 각 카드 상단에 구분 아이콘과 짧은 제목을 둡니다.
- 빠른 입력 예시 칩은 입력 아래에 두고 수평 스크롤보다 줄바꿈을 우선합니다.
- 가상 키보드가 다음 버튼을 가리지 않게 입력 포커스 시 행동 영역을 문서 흐름으로 전환합니다.

### Page 03. 오래 이어온 방법

- Page 01과 같은 선택 카드 구조를 재사용합니다.
- 성취를 평가하는 아이콘, 점수와 트로피 표현은 사용하지 않습니다.
- 카드 설명은 오래 이어진 조건에 초점을 둡니다.

### Page 04. 바꾸고 싶은 생활 영역

- 짧은 생활 영역 카드를 모바일 2열, 태블릿 이상 3~4열로 표시합니다.
- 선택 순서를 각 카드 오른쪽 위 `1순위`, `2순위`, `3순위` 배지로 표시합니다.
- 선택 가능한 최대 수와 현재 선택 수를 질문 아래에 텍스트로 안내합니다.
- 200% 확대 또는 360px 이하에서는 1열로 전환할 수 있습니다.

### Page 05. LIFE SESSION 안내

- `60분 · 1:1 오프라인`을 상단 정보 라벨로 표시합니다.
- 프로그램 설명은 하나의 긴 문단보다 `듣기 → 살펴보기 → 함께 정하기 → 시작 준비 → 마무리`의 5개 짧은 카드로 분리합니다.
- 시간 정보는 보조 배지로 제공하고 내용 제목이 먼저 읽히게 합니다.
- 7일 뒤 후속 만남은 Warm Ivory 보조 카드로 분리합니다.
- CTA는 `신청 정보 입력하기`로 다음 행동을 명확히 씁니다.

### Page 06. 신청 정보

- 입력을 `기본 정보`, `가능한 일정`, `개인정보 동의`의 3개 카드 그룹으로 나눕니다.
- 모든 입력은 레이블을 화면에 표시하고 placeholder만으로 설명하지 않습니다.
- 오류는 해당 필드 아래와 제출 오류 요약 영역에 함께 표시합니다.
- 개인정보 안내는 Warm Ivory 면 위에 수집 항목, 목적, 보유 기간을 먼저 보여준 뒤 동의를 받습니다.
- 제출 버튼은 `LIFE SESSION 신청하기`처럼 결과가 분명한 문구를 사용합니다.

### 완료 화면

- Sage Green 체크 또는 단순 기하 패턴으로 완료를 표시합니다.
- `신청이 완료됐어요` 제목, 다음 안내, 접수번호 순으로 보여줍니다.
- 접수번호는 복사 가능한 별도 카드로 제공합니다.
- 다시 시작하기는 보조 행동으로 낮은 위계에 둡니다.

## 11. 반응형 기준

| 구간 | 화면 구성 |
| --- | --- |
| `< 360px` | 좌우 16px, 모든 기본 선택 1열, 정보 카드 1열 또는 2+1열 |
| `360~599px` | 좌우 20px, 기본 선택 1열, 짧은 생활 영역 2열 |
| `600~839px` | 최대 560px 중앙 단일 열, 생활 영역 2~3열 |
| `840~1279px` | 최대 640px 패널, 신청 정보만 최대 720px |
| `≥ 1280px` | 넓은 여백 속 최대 720px, 카드 폭 과확장 금지 |

### 높이 대응

- `100dvh`를 기준으로 하되 콘텐츠를 한 화면에 억지로 맞추지 않습니다.
- 640px 미만 높이에서는 중앙 수직 정렬을 해제합니다.
- 고정 헤더와 고정 하단 CTA를 동시에 사용하지 않습니다.
- 모바일의 성공 기준은 무스크롤이 아니라 가로 잘림, 입력 가림과 CTA 접근 불가가 없는 것입니다.

## 12. 모션

- 화면 전환은 `180~240ms` 페이드와 `8px` 이내의 짧은 수직 이동을 사용합니다.
- 카드 선택은 `140~180ms` 안에 테두리, 배경과 체크가 바뀝니다.
- CTA Hover는 `1px` 상승, Pressed는 원래 위치로 돌아오는 정도로 제한합니다.
- 반복 애니메이션, 종이 넘김, 카드 흔들림과 장식용 패럴랙스는 사용하지 않습니다.
- `prefers-reduced-motion`에서는 위치 이동을 제거하고 상태를 즉시 표시합니다.

## 13. 접근성 기준

- 본문과 컨트롤은 WCAG AA 명도 대비를 충족해야 합니다.
- 모든 터치 영역은 최소 `44×44px`을 유지합니다.
- 라디오, 체크박스와 입력은 실제 HTML 컨트롤을 유지합니다.
- 선택, 현재 단계, 오류와 완료를 색만으로 구분하지 않습니다.
- 화면 전환 후 질문 제목으로 포커스를 옮깁니다.
- 진행률은 화면 낭독기에서 현재 단계와 전체 단계를 이해할 수 있게 합니다.
- sticky 행동 영역이 200% 확대, 키보드 탐색과 모바일 가상 키보드에서 콘텐츠를 가리지 않아야 합니다.
- 장식용 기하 그래픽은 `aria-hidden="true"`로 처리합니다.
