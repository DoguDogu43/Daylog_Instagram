# 데이로그 카피 가이드

- 작성일: 2026-09-01
- 상태: 작성 원칙 확정·운영 용어 일부 확인 필요
- 적용 대상: 홈페이지와 LIFE NOTE 신청폼의 사용자 노출 문구

## 1. 독자와 목표

모든 문구는 중학교 2학년이 데이로그나 코칭에 관한 배경지식 없이 읽어도 한 번에 뜻과 다음 행동을 알 수 있어야 합니다. 쉬운 말은 가벼운 말이 아닙니다. 친절하되 사실과 조건을 정확하게 씁니다.

## 2. 기본 말투

- 존댓말 `-해요`, 요청형 `-해 주세요`를 기본으로 사용합니다.
- 사용자가 해야 할 행동이나 결과를 문장 앞에 둡니다.
- 한 문장에는 한 가지 정보나 행동만 담습니다.
- 사용자를 탓하지 않고, 문제가 생기면 해결 방법을 함께 안내합니다.
- 과도한 느낌표, 유행어, 반말과 장식용 이모지는 사용하지 않습니다.
- 브랜드 고유 이름을 제외한 불필요한 영문 대문자 표기를 줄입니다.

## 3. 문장 길이

| 유형 | 기본 기준 |
| --- | --- |
| 화면 제목 | 15~30자, 모바일 2~3줄 이내 |
| 화면 설명 | 문장당 40~60자 이내, 최대 2문장 |
| 선택지 제목 | 2~12자 |
| 선택지 설명 | 15~40자 |
| 버튼 | 2~16자, 누른 뒤 결과를 동사로 표현 |
| 도움말·오류 | 1~2문장, 이유나 해결 행동 포함 |
| 로딩 | 1문장, 현재 작업과 중복 실행 방지 안내 |
| 완료 | 2~3문장, 완료 사실·연락 시점·다음 절차 안내 |

문장을 줄이면 뜻이 빠지는 경우에는 길이보다 정확성을 우선합니다.

## 4. 데이로그 용어표

| 개념 | 사용자 노출 기준 | 사용하지 않을 표현 | 비고 |
| --- | --- | --- | --- |
| 회사 | `데이로그` | `DAYLOG` 반복 표기 | 로고·고유 라벨에서는 영문 사용 가능 |
| 질문 과정 | `생활 질문 노트` | 진단, 검사 | 첫 등장 뒤에는 `질문`으로 줄여 사용 |
| 프로그램 | `60분 1:1 생활 세션` | `LIFE SESSION` 단독 표기 | 영문을 쓸 때 첫 등장에 우리말 설명 병기 |
| 대화 | `생활에 관한 대화` | 인터뷰 | 내부 데이터 이름 `interview`와 대응 |
| 행동 설계 | `지금 시작할 행동` | 루틴 설계, 솔루션 | `루틴`이 필요하면 `반복할 행동`으로 설명 |
| 신청 상태 | `신청` | 접수, 예약, 등록 혼용 | 사용자 화면에서는 `신청`으로 통일 |
| 연락 | `문자`, `전화` | 별도 안내, 추후 연락 | 실제 방법과 기한을 함께 표시 |
| 장소 | `만나기 편한 지하철역` | 거주지, 상세 주소 | 실제 주소는 수집하지 않음 |
| 기록 보관 | `신청일부터 3개월 뒤 삭제` | 일정 기간 보관 | 기간과 삭제 시점을 숫자로 표시 |
| 선택 없음 | `아직 잘 모르겠어요` | 해당 없음 | 판단받는 느낌을 줄임 |

## 6. 숫자와 운영 정보

- 날짜는 `2026년 9월 1일`, 시간은 `오후 2시`, 기간은 `3개월`처럼 적습니다.
- 연락 기한, 연락 방법, 비용, 지역과 취소 기준은 운영에서 확인한 값만 사용합니다.
- 운영 정보가 정해지지 않았으면 `곧`, `추후`, `확인 후`로 숨기지 않습니다. 문서에 `운영 확정 필요`로 남기고 화면 확정을 보류합니다.

## 7. 오류와 로딩

오류는 `무엇이 문제인지 + 어떻게 고칠지` 순서로 씁니다.

```text
나이를 1~120 사이 숫자로 입력해 주세요.
전화번호를 010-0000-0000 형식으로 입력해 주세요.
신청 내용을 보내지 못했어요. 입력한 내용은 화면에 남아 있어요. 잠시 후 다시 신청해 주세요.
```

제출 중에는 현재 작업과 중복 실행 방지를 함께 알립니다.

```text
신청 내용을 보내고 있어요. 다시 누르지 마세요.
```
