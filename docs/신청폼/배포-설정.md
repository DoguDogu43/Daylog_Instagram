# Vercel 배포 설정

## 프로젝트 설정

| 항목 | 값 |
| --- | --- |
| Framework Preset | Vite |
| Root Directory | `application-form` |
| Install Command | `npm install` |
| Build Command | `npm run build` |
| Output Directory | `dist` |

저장소 루트 자체를 Vercel 프로젝트로 연결하는 경우 Root Directory를 `application-form`으로 지정합니다. `application-form`만 별도 저장소로 연결하면 Root Directory는 비워둡니다.

## 환경변수

| 이름 | 값 | 범위 |
| --- | --- | --- |
| `GOOGLE_APPS_SCRIPT_URL` | 통합 Apps Script `/exec` URL | 서버 전용 |
| `GOOGLE_APPS_SCRIPT_SHARED_SECRET` | `DAYLOG_LIFE_SESSION_SECRET`과 같은 값 | 서버 전용 |
| `DAYLOG_FORM_TYPE` | `daylog_life_session` | 서버 전용 |
| `APPS_SCRIPT_TIMEOUT_MS` | `9000` 권장 | 서버 전용 |

비밀값에 `VITE_` 접두어를 사용하지 않습니다. `VITE_`로 시작한 값은 브라우저 번들에 공개될 수 있습니다.

## 배포 순서

1. 통합 Apps Script에 데이로그 라우팅과 `DaylogLifeSession.gs`를 추가합니다.
2. Apps Script 스크립트 속성에 비밀값을 등록합니다.
3. Apps Script 웹 앱을 새 버전으로 배포합니다.
4. Vercel Project Settings에서 환경변수를 등록합니다.
5. Preview 배포에서 테스트 신청을 보냅니다.
6. 세 데이로그 탭과 중복 방지를 확인합니다.
7. 기존 폼 회귀 테스트를 완료합니다.
8. Production으로 배포합니다.

## 로컬 확인

화면만 확인할 때는 다음 명령을 사용합니다.

```bash
npm run dev
```

Serverless Function과 환경변수까지 함께 확인할 때는 Vercel CLI 개발 환경을 사용합니다. 실제 비밀값은 `.env` 계열 로컬 파일에만 두고 Git에 커밋하지 않습니다.
