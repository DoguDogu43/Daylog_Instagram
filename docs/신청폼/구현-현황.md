# 신청폼 구현 현황

## 현재 상태

React, TypeScript와 Vite 기반 초기 신청 경험을 구현했습니다. 배포 대상은 Vercel이며, 최종 신청과 퍼널 이벤트는 동일 출처 Serverless Function을 거쳐 기존 통합 Google Apps Script로 전달하도록 구성했습니다.

신청 경험은 `4단계 생활 기록 → LIFE SESSION 안내 → 신청 정보 입력 → 신청 완료` 흐름입니다. 별도 LIFE NOTE 답변 요약 화면은 사용하지 않습니다.

구현 경로:

```text
application-form/
```

## 브랜드 경험

참고 사이트의 음악·레코딩 세계관을 복제하지 않고 다음 구조적 장점만 데이로그에 맞게 해석했습니다.

- 전체 화면에서 브랜드 문장을 강하게 제시하는 인트로
- 현재 상태를 알려주는 짧은 영문 레이블과 단계 번호
- 한 번에 하나의 질문에 집중하는 흐름
- 큰 CTA와 다음 행동을 설명하는 보조 문구
- 선택이 누적되며 빈 줄이 채워지는 `나의 하루 노트`

화면의 중심 이미지는 제거했습니다. 첫 화면부터 질문, 연락 신청과 완료까지 종이, 가로줄, 체크, 메모와 도장으로 이어지는 노트형 디자인을 사용합니다. 코치 사진이나 하단 인물 이미지를 렌더링하지 않습니다.

페이지 내비게이터는 노란 종이 조각과 분홍색 현재 페이지로 구성한 포스트잇 형태를 사용합니다. 표지의 대표 문장은 분홍 형광펜으로 강조하고, 질문과 프로그램 안내의 전진 버튼은 Growth Yellow, 시작과 최종 제출 버튼은 Deep Navy로 역할을 구분합니다. Sage Green은 완료 화면의 도장처럼 실제 완료 상태에만 사용합니다.

## 화면 흐름

```text
인트로
  → 하루 리듬
  → 편안한 순간·버거운 순간
  → 과거의 지속 방식
  → 바꾸고 싶은 생활 영역 순위
  → LIFE SESSION 프로그램 안내
  → 신청자·인터뷰 일정 정보
  → 신청 완료
```

## 구현된 질문

| 단계 | 질문 | 입력 방식 |
| --- | --- | --- |
| 1 | 요즘 하루는 어떤 리듬으로 흘러가나요? | 단일 선택 |
| 2 | 가장 편안한 순간과 가장 버거운 순간은 언제인가요? | 각 1~100자 자유 텍스트와 빠른 힌트 칩 |
| 3 | 오래 이어가 본 일이 있나요? | 단일 선택 |
| 4 | 가장 먼저 바꾸고 싶은 곳은 어디인가요? | 누른 순서대로 1~3순위 선택 |

## 연락 신청 항목

- 필수: 이름
- 필수: 나이
- 필수: 전화번호(`010-0000-0000`)
- 필수: 거주지 주변 역
- 필수: 인터뷰 가능 요일과 시간대
- 필수: 개인정보 수집·이용 동의
- 사용자에게 보이지 않는 스팸 방지 필드

개인정보 안내에는 실제 수집 항목, 체험 프로그램 신청·인터뷰 안내 목적과 신청일로부터 3개월 보유 기간을 표시합니다.

## 데이터 처리

- 생활 탐색 답변만 `sessionStorage`에 임시 저장합니다.
- 신청 개인정보는 브라우저 저장소에 저장하지 않습니다.
- 제출 재시도 시 같은 접수번호를 사용합니다.
- 퍼널 이벤트에는 질문 답변과 개인정보를 넣지 않습니다.
- Vercel API에서 허용값, 길이, 연락처 형식과 식별자 형식을 재검증합니다.
- Apps Script 비밀값과 URL은 서버 환경변수에서만 읽습니다.
- Google Sheets에는 접수번호와 이벤트 ID 기준 중복 방지를 적용합니다.
- 데이터 스키마는 `daylog-life-session-v3`를 사용합니다.
- 퍼널은 4개 질문 이벤트 다음 `session_info_viewed`, `application_started`로 이어집니다.
- `npm test`의 7개 계약 테스트가 프론트·API·Apps Script의 스키마, 문자열 시간, 순위 데이터, 신청 필드, 퍼널 순서와 재시작 ID 회귀를 검사합니다.

## 반응형 UI

- 노트 콘텐츠는 모든 너비에서 붉은 세로선보다 최소 14px 오른쪽, 첫 가로줄 아래에서 시작합니다.
- 360px 이하에서도 붉은 세로선을 유지하며 본문과 카드의 가로 넘침을 방지합니다.
- 1280×720 화면에서 첫 화면 CTA가 스크롤 전에 보입니다.
- 600~839px에서는 작성된 항목과 현재 기록을 중심으로 노트 높이를 줄입니다.
- 599px 이하에서는 헤더를 축소하고 중요도가 낮은 종이 장식을 줄입니다.
- 질문 화면에는 선택 답변 노트 미리보기와 별도 완성 노트를 렌더링하지 않습니다.
- 599px 이하 질문 화면에서는 일반 선택 카드를 읽기 쉬운 1열, 생활 영역을 2열로 배치합니다.
- 700px 이하의 낮은 화면에서도 글자를 과도하게 줄이지 않고 필요한 세로 스크롤을 허용합니다.
- 모바일 기준은 한 화면 무스크롤이 아니라 가로 잘림 방지, 자연스러운 세로 스크롤, 가상 키보드가 입력과 제출 행동을 가리지 않는 것입니다.
- 선택 상태는 24% Yellow 배경, 2px Deep Navy 테두리·체크와 Yellow 표시로 구분합니다.
- Page 02의 텍스트 입력창은 불투명한 단색 배경을 사용해 노트 가로줄이 비치지 않습니다.
- 데스크톱에서는 작성된 노트 문장을 14px 이상으로 표시하고 모바일에서는 현재 줄만 간결하게 축소합니다.

## 남은 운영 작업

- 배포 환경에서 프론트, Vercel API와 Apps Script의 v3 계약을 실제 요청으로 최종 통합 확인
- 실제 신청 완료 후 다시 시작할 때 `sessionId`와 `requestId`가 새로 생성되는지 운영 회귀 확인
- 실제 통합 Apps Script의 `Main.gs`에 데이로그 비밀키 매핑과 분기 추가
- `DaylogLifeSession.gs`를 실제 Apps Script 프로젝트에 추가
- Apps Script 스크립트 속성에 `DAYLOG_LIFE_SESSION_SECRET` 등록
- Vercel 환경변수 등록
- Apps Script와 Vercel 재배포
- 테스트 신청 후 데이로그 전용 세 탭 생성 및 기록 확인
- 공개 개인정보 처리방침의 보관 기간과 파기 절차 확정
