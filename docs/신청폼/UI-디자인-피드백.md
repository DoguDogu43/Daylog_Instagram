## 당시 확정한 제품 방향

LIFE NOTE는 신청폼을 노트처럼 느끼게 하는 시각적 장치입니다. 사용자가 실제로 긴 글을 써야 하는 일기 서비스로 만들지 않습니다.

- `짧게 선택 → 노트 문장 자동 작성 → 최소 연락 정보 입력 → 신청 완료` 순서를 사용합니다.
- 생활 탐색에는 필수 자유 입력을 두지 않습니다.
- 이름·호칭, 연락 방법, 연락처와 개인정보 동의만 신청 필수값으로 둡니다.
- 희망 요일, 희망 시간대와 추가 이야기는 선택 입력으로 둡니다.
- 노트 장식보다 질문, 입력, 오류와 CTA가 먼저 보여야 합니다.
- 전체 목표 시간은 약 3분입니다.

## 최종 PM 결정: 질문 화면 단순화

2026-08-27 재검토에서 브랜드 아트디렉터, 전환 UX 디자이너와 디자인 시스템 프론트엔드의 의견이 다음 방향으로 일치했습니다.

- 질문 단계는 `질문 → 선택 → 다음`에만 집중합니다.
- 질문 하단과 우측의 선택 답변 노트 미리보기는 완전히 제거합니다.
- 누적 답변은 최종 요약의 완성 노트에서 한 번만 보여줍니다.
- 일반 모바일 선택지는 1열로 바꾸고 제목 글자 크기와 터치 영역을 키웁니다.
- 생활 영역은 기본 2열, 700px 이하 저높이 화면에서는 제목 중심 3열을 사용합니다.
- 미선택 `+`, 생활 영역 영문 마커, 코치 메모 박스와 질문 화면의 제본·세로선을 제거합니다.
- Growth Yellow는 진행선, 선택선과 CTA 아이콘에만 제한적으로 사용합니다.
- 로고, 진행선, 질문 제목, 선택 영역과 버튼은 같은 본문 정렬축을 사용합니다.

이 결정은 아래 초기 검토의 실시간 노트 강화 권고보다 우선합니다. 노트 세계관은 첫 화면, 페이지 진행 표시와 최종 요약에서 유지합니다.

## 검토 목적

신청폼이 다음 세 가지 목표를 동시에 달성하는지 확인했습니다.

1. 데이로그의 따뜻하고 전문적인 브랜드 인상을 전달하는가
2. 사용자가 Life Session 신청 과정임을 빠르게 이해하는가
3. 데스크톱과 모바일에서 질문, 선택, 기록, 신청 흐름이 명확한가

서로 다른 역할을 가진 세 명의 검토 관점을 사용했습니다.

| 역할 | 주요 검토 기준 |
| --- | --- |

| 전환 UX 디자이너 | 첫 3초의 목적 이해, CTA 발견성, 질문 기대와 실제 행동의 일치 |

## 종합 판단

현재 UI는 큰 한국어 헤드라인, Growth Yellow 밑줄과 단정한 선택 카드를 통해 데이로그만의 인상을 만듭니다. 질문 화면은 중앙 단일 열로 정리하고 답변 결과는 최종 노트에서만 보여줍니다.

다만 현재 첫 화면만 보면 독립적인 하루 기록 서비스처럼 보이며, 오프라인 Life Session 신청으로 이어진다는 목적이 늦게 드러납니다. 노트도 핵심 결과물보다는 작은 장식처럼 보이고, 선택 상태와 안내 메모에서 노란색이 과도하게 경쟁합니다. 낮은 데스크톱 화면과 모바일에서는 CTA와 전체 노트가 흐름을 길게 만드는 문제가 있습니다.

전면 재설계는 필요하지 않습니다. 현재 구조를 유지하면서 목적 전달, 노트 가독성, 색상 위계와 반응형 밀도를 보완하는 방향이 적합합니다.

## 출시 전 우선순위

### P0. 신청 목적을 첫 화면에 명시

사용자는 첫 화면에서 하루를 기록한 뒤 무엇이 이어지는지 바로 이해해야 합니다.

권장 목적 문구:

> 3분간 하루를 기록하고  
> 60분 오프라인 LIFE SESSION을 신청합니다.

권장 CTA:

> 하루 기록하고 세션 알아보기 →

가격, 진행 지역, 운영 시간과 신청 후 연락 시점도 연락처 입력 전에 확인할 수 있어야 합니다. 실제 운영 정보가 확정되지 않았다면 임의의 값을 표시하지 않고 운영 정보 확정 작업으로 분리합니다.

### P0. 시간 선택의 미응답 상태 보장

편안한 시간과 힘든 시간이 사용자의 조작 없이 기본값으로 제출되면 실제 답변과 저장 데이터가 달라집니다. 시간 질문은 초기 미선택 상태를 제공하고 사용자가 직접 선택한 뒤에만 다음 단계로 이동할 수 있어야 합니다.

### P1. 최종 노트를 핵심 결과물로 강화

권장 표시 기준:

| 요소 | 권장값 |
| --- | --- |
| 노트 제목 | 25~26px |
| 항목 이름 | 12px 이상 |
| 작성된 내용 | 14~15px, 줄높이 약 1.5 |
| 보조 텍스트 | Deep Navy 기준 65~70% 이상의 대비 |
| 현재 작성 항목 | 더 진한 색과 명확한 강조 |
| 미작성 항목 | 단순한 빈 줄 또는 약한 자리 표시 |

외부 화면과 노트 내부에서 제본, 테이프, 회전, 종이 겹침과 그림자를 동시에 반복하지 않습니다. 전체 화면은 차분한 아이보리 편집물로 정리하고 실제 노트 영역에만 종이 질감을 집중합니다.

### P1. 선택 카드의 노란색 사용 축소

선택 상태는 다음 기준으로 단순화합니다.

- 배경은 Growth Yellow의 약 12~16% 농도로 사용
- Deep Navy 1~1.5px 테두리 사용
- 체크 아이콘은 Deep Navy로 표시
- 노란색은 왼쪽 또는 상단의 3~4px 포인트로 제한
- 노란색의 두꺼운 그림자 제거
- 키보드 포커스는 3px Deep Navy 외곽선과 약 3px 간격으로 별도 표시

선택하지 않은 상태에서 다음 버튼이 활성화된 것처럼 보이지 않도록 비활성 시각 상태도 분명히 구분합니다.

### P1. 첫 화면 정보 밀도 축소

첫 화면은 다음 순서를 권장합니다.

1. 서비스 목적 한 줄
2. 메인 헤드라인
3. 짧은 설명 한 문단
4. CTA
5. `5개의 짧은 선택 · 약 3분` 보조 문구

기존 3개 설명 항목은 CTA 아래로 이동하거나 삭제합니다. 노란 안내 메모는 별도 박스로 경쟁시키지 않고 CTA의 보조 문구로 통합합니다. 안내 영역과 CTA의 너비도 동일하게 맞춥니다.

### P1. 낮은 데스크톱 화면 대응

화면 높이가 820px 이하인 데스크톱에서는 첫 화면과 질문 화면의 CTA가 초기 화면 안에 들어오도록 밀도를 낮춥니다.

- 인트로와 질문 화면의 상하 여백 축소
- 질문과 선택지 사이 간격 축소
- 안내 메모와 오류 영역의 여백 축소
- 첫 화면의 설명 목록을 가로형으로 바꾸거나 축약
- 1280×720 화면에서 스크롤 전 CTA 일부 또는 전체 노출

### P1. 모바일 질문 노트 제거

질문마다 선택 답변 노트를 반복해서 보여주지 않습니다. 질문 화면에는 질문, 선택과 다음 행동만 표시하고 최종 요약에서 전체 노트를 공개합니다.

| 화면 너비 | 권장 방식 |
| --- | --- |
| 840px 미만 | 질문 단계의 노트 미리보기 제거 |
| 840px 이상 | 질문 단계의 노트 미리보기 제거, 중앙 단일 열 사용 |
| 최종 요약 | 전체 노트 공개 |

320px 폭에서는 제본 여백 때문에 본문이 지나치게 좁아지지 않도록 오른쪽 여백과 장식 폭을 함께 줄입니다.

### P1. 입력 오류와 포커스 개선

- 오류가 있는 입력 요소에 `aria-invalid` 적용
- 오류 발생 시 첫 번째 오류 입력으로 포커스 이동
- 입력 요소 가까이에 오류 문구 표시
- 색상만으로 오류나 선택 상태를 구분하지 않기
- 컨테이너의 세로 `overflow` 설정이 연락처 영역의 sticky 동작을 막지 않는지 확인

### P2. 글자 크기와 장식 정리

- 선택지 제목은 15~16px 권장
- 선택지 설명은 12.5~13px 권장
- 단계, 노트 항목과 의미 있는 보조 문구는 최소 12px 사용
- 외곽 종이 가로줄의 불투명도 축소
- 선택 카드와 시간 선택 영역의 반복 종이 질감 제거
- 회전은 약 0.5~0.8도로 제한
- 테이프와 겹친 종이 그림자의 대비 완화

## 카피와 실제 행동의 일치

현재 `한 페이지를 적는다`는 표현은 자유 입력을 예상하게 하지만 실제 흐름은 대부분 선택형입니다. MVP에서는 실제 행동과 일치하도록 다음 문구를 권장합니다.

> 5개의 짧은 선택으로 오늘의 하루를 정리해보세요.

MVP에서는 별도의 `오늘의 한 줄` 자유 입력을 추가하지 않습니다. 선택한 답변을 자연스러운 1인칭 문장으로 자동 작성해 노트 경험을 만들고, 직접 적고 싶은 내용은 연락 단계의 선택 입력인 `추가 이야기`에서만 받습니다.

## 유지할 디자인 요소

- 큰 한국어 헤드라인과 손으로 그은 듯한 Growth Yellow 밑줄
- 질문, 선택과 다음 CTA가 이어지는 중앙 단일 열
- 선택 결과를 최종 요약에서 완성 노트로 보여주는 방식
- Deep Navy CTA와 노란 원형 화살표
- Warm Ivory, Deep Navy와 Growth Yellow 중심의 브랜드 컬러
- 신청 결과를 진단이 아닌 `함께 이어 쓸 하루 초안`으로 표현하는 태도

## PM 실행 순서

1. 첫 화면에 Life Session 신청 목적과 운영 정보 표시
2. 연락 신청의 필수값을 최소화하고 일정·추가 이야기를 선택 입력으로 변경
3. 시간 선택 초기값과 다음 버튼 상태 수정
4. 질문 단계 노트 미리보기 제거와 최종 노트 위계 강화
5. 선택 카드와 안내 메모의 노란색 사용 축소
6. 낮은 데스크톱 화면에서 CTA 노출 보장
7. 모바일 질문 화면의 노트 미리보기 제거
8. 오류, 포커스와 sticky 동작 검수
9. 실제 iPhone Safari, Android Chrome과 태블릿에서 최종 확인
