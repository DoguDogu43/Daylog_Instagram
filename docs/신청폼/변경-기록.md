# 신청폼 변경 기록

## 2026-08-27

### 단일 스프링 노트(Spiral Notebook) 전면 개편 및 가독성 최적화

- 텍스트 및 카드 잘림의 원인이었던 좌우 2열 분할을 전면 제거하고 중앙 단일 스프링 노트(`max-width: 820px`)로 통일했습니다.
- 상단 14개 와이어-오(Wire-O) 듀얼 코일 링, 웜 아이보리 내지, 가로 줄눈선과 좌측 레드 마진 세로선으로 실제 스프링 노트 질감을 정갈하게 구현했습니다.
- 상단 인덱스 탭 네비게이션(`[표지] [01 리듬] [02 온도] [03 지속] [04 습관] [05 동행] [초안] [신청]`)을 추가하여 진행 상황 확인 및 이전 질문 즉시 이동을 지원합니다.
- 첫 화면(Intro)에서 장소, 시간, 일정과 관련된 나열 뱃지를 제거하고 `나에게 맞는 하루를 설계해볼게요.`로 명확하고 간결하게 정돈했습니다.
- 02단계(하루의 온도)를 24시간 선택 목록에서 사용자가 자신의 일상 속 편안한 순간과 버거운 순간을 직접 텍스트로 타이핑하거나 빠른 힌트 칩으로 입력할 수 있는 입력 카드 UI로 전환했습니다.
- API 및 데이터 스키마에서 `comfortableTime`과 `difficultTime`을 텍스트 문자열(1~100자)로 안전하게 수용하도록 업데이트했습니다.

### 아날로그 기록 경험 및 인터랙션 고도화

- **실시간 다이어리 스플릿 뷰(Split Layout)**: 데스크톱/태블릿 질문 화면에서 좌측(질문지)과 우측(실시간으로 한 줄씩 적히는 나의 다이어리 속지)이 양면으로 펼쳐지도록 구현했습니다.
- **사각사각 만년필 잉크 작성 애니메이션**: 질문 항목을 선택할 때마다 다이어리 속지의 가로줄(Lined Paper)에 글씨가 잉크로 슥 써내려가는 듯한 부드러운 필기 모션(`inkWriteIn`)을 적용했습니다.
- **다이어리 인덱스 스티커 탭**: 상단 및 다이어리 우측에 5단계 색인 탭(01 리듬, 02 시간, 03 지속, 04 영역, 05 동행)을 배치하여 진행 상태를 직관적으로 파악하고 클릭 시 즉시 해당 단계로 이동/수정할 수 있도록 했습니다.
- **문구류 아날로그 디테일**: 바인더 링 펀치 구멍, 마스킹 테이프(`washi-tape`), 포스트잇, 연필 체크 스탬프(`stampPop`), 붉은 왁스 실링 스탬프(`wax-seal-stamp`), 책갈피 리본(`bookmark-ribbon`)을 적용했습니다.
- **모바일 라이브 다이어리 미니 배너**: 모바일 화면 상단에 콤팩트한 다이어리 한 줄 띠지를 배치하여 선택 즉시 기록 문장이 업데이트되는 손맛을 제공합니다.
- **연락처 화면 다이어리화**: 다이어리 맨 뒷장의 '소유자 정보(Owner Info)' 네임택 포켓 스타일로 정돈했습니다.

### 모바일 한 화면 최적화

- 모바일 헤더와 화면 여백을 줄이고 각 단계를 화면 높이 기준으로 배치했습니다.
- 일반 질문 선택 카드는 읽기 쉬운 1열, 생활 영역 카드는 기본 2열로 구성했습니다.
- 질문 중 선택 답변 노트 미리보기를 완전히 제거하고 완성 결과는 최종 요약에서만 보여줍니다.
- 700px 이하 화면의 생활 영역만 제목 중심 3열로 전환해 우선순위 선택과 다음 CTA까지 한 화면에 유지합니다.
- 연락 화면은 필수 연락 정보와 동의, 제출 버튼이 먼저 보이도록 압축했습니다.
- 700px 이하의 낮은 연락 화면에서는 선택 일정·메모와 긴 동의 설명을 숨겨 신청 필수 흐름을 한 화면에 유지합니다.
- 390×844와 320×568 브라우저 뷰포트에서 인트로, 질문, 요약과 기본 연락 화면의 세로 스크롤이 생기지 않는 것을 확인했습니다.

### 질문 UI 가독성 개선

- 질문 화면을 중앙 단일 열로 바꾸고 답변 외의 보조 패널을 제거했습니다.
- 코치 메모 박스, 미선택 카드의 `+`, 생활 영역 영문 마커와 중복 종이 장식을 제거했습니다.
- 질문 단계 표기를 간단한 섹션명과 `현재 / 전체` 숫자로 정리했습니다.
- 모바일 선택 제목을 키우고 시간 레이블, 도움말, 오류와 우선순위 칩을 읽을 수 있는 크기로 높였습니다.
- 선택 카드는 단색 종이 면, Navy 테두리와 얇은 Yellow 선택선만 사용하도록 단순화했습니다.
- 다음 행동 문구를 `다음`, 마지막 질문은 `내 하루 요약 보기`로 짧게 바꿨습니다.

### 질문 화면 정렬 보완

- 데스크톱에서 로고, 진행선, 질문 제목, 선택 카드와 하단 버튼의 왼쪽·오른쪽 기준선을 통일했습니다.
- 진행선을 화면 끝에서 본문 폭 안으로 옮겨 질문 영역과 하나의 구성처럼 보이게 했습니다.
- 카드 안쪽 여백과 카드 사이 간격을 정리하고 보조 문장의 대비를 높였습니다.
- 모바일에서는 로고와 질문 본문의 왼쪽 기준선을 맞추고 선택 제목을 15px로 높였습니다.
- 320×568에서 일반 질문과 우선 영역이 펼쳐진 생활영역 질문이 한 화면에 유지되는 것을 다시 확인했습니다.

### 간편 신청 흐름 적용

- 첫 화면에서 `3분 기록 후 60분 오프라인 LIFE SESSION 신청` 목적을 바로 안내합니다.
- 시작 CTA를 `내 하루 적고 신청하기`로 변경하고 `5개의 짧은 선택 · 약 3분`을 함께 표시합니다.
- 긴 글을 쓰지 않아도 선택 답변이 자연스러운 노트 문장으로 자동 작성되게 했습니다.
- 희망 요일, 희망 시간대와 추가 이야기를 선택 입력으로 변경했습니다.
- 선택 입력을 `일정과 메모 추가하기` 안에 접어 기본 연락 신청 화면을 짧게 만들었습니다.
- 연락 신청의 필수값을 이름·호칭, 연락 방법, 연락처와 개인정보 동의로 제한했습니다.

### LIFE NOTE UI 보완

- 선택 카드의 강한 Yellow 면과 그림자를 줄이고 Navy 테두리, 체크와 얇은 Yellow 표시로 정리했습니다.
- LIFE NOTE 제목, 항목과 작성 문장의 글자 크기·대비를 높였습니다.
- 외곽 노트 줄과 제본 장식의 농도를 낮추고 실제 노트 영역에만 종이 표현을 집중했습니다.
- 1280×720 화면에서도 첫 CTA가 초기 화면 안에 들어오도록 세로 여백을 줄였습니다.
- 질문 화면에서는 작성 중인 노트를 표시하지 않고 전체 노트는 최종 요약에서만 표시합니다.

### 데이터와 접근성 보완

- 편안한 시간과 힘든 시간의 기본값을 제거하고 사용자가 직접 선택해야 다음 단계로 이동하게 했습니다.
- 시간 입력을 미선택 상태가 있는 접근 가능한 선택 목록으로 변경했습니다.
- 필수 선택 전 다음 CTA를 비활성화하고 선택·포커스 상태를 분리했습니다.
- 연락 입력 오류 시 첫 오류 입력으로 포커스를 이동하고 `aria-invalid`를 적용했습니다.
- 클라이언트, Vercel API와 Apps Script에서 빈 희망 일정 배열을 허용하도록 변경했습니다.
- 완성 노트 확인 퍼널 이벤트를 `life_note_viewed`로 통일했습니다.
- 비 JSON 오류 응답에서도 기술 문구 대신 안전한 한국어 오류를 표시합니다.

## 2026-08-25

### 초기 구현

- React, TypeScript, Vite 프로젝트를 생성했습니다.
- Vercel 배포를 전제로 브라우저 UI와 Serverless Function을 분리했습니다.
- 데이로그 브랜드 컬러인 Deep Navy, Growth Yellow, Warm Ivory와 Sage Green을 적용했습니다.
- 5개의 생활 탐색 질문, DAY ORBIT, 하루 지도 요약과 연락 신청을 구현했습니다.
- 모바일, 태블릿과 데스크톱 반응형 스타일을 적용했습니다.
- 키보드 입력, 포커스 이동, 오류 알림과 모션 감소 설정을 반영했습니다.

### 참고 사이트 반영

- `https://apply.hyukrecord.com/`의 강한 인트로, 짧은 상태 레이블, 단계 번호와 큰 CTA 구조를 참고했습니다.
- 참고 사이트의 음악·레코딩 문구와 시각 세계관은 사용하지 않았습니다.
- 데이로그의 핵심 서사인 사람, 대화, 발견과 하루의 움직임으로 다시 구성했습니다.

### 이미지 제거

- 요청에 따라 첫 화면 하단의 코치 이미지를 제거했습니다.
- 신청폼이 참조하던 이미지 파일도 제거했습니다.
- 첫 화면의 임팩트는 대형 문장, 궤도 그래픽과 상태 레이블로 유지했습니다.
- 별도 브랜드 원본 에셋은 수정하지 않았습니다.

### Google Sheets 연동

- `/api/daylog/application`에 최종 신청 검증과 중계 로직을 구현했습니다.
- `/api/daylog/track`에 개인정보 없는 퍼널 기록 로직을 구현했습니다.
- 데이로그 전용 `DaylogLifeSession.gs`를 추가했습니다.
- 접수번호와 이벤트 ID 중복 방지, honeypot, 서버 전용 비밀값, 문자열 길이와 enum 검증을 반영했습니다.
- 기존 `총합_시트_관련` 문서는 수정하지 않았습니다.

### LIFE NOTE 디자인 전환

- 신청폼의 중심 메타포를 원형 하루 지도에서 `내 하루를 적는 노트`로 변경했습니다.
- 첫 화면을 큰 노트 캔버스, 제본 표시, 가로줄과 빈 기록 페이지로 다시 구성했습니다.
- 선택 카드를 메모지와 체크 항목처럼 보이도록 변경했습니다.
- 질문에 답할 때 오른쪽 `나의 하루 초안`의 빈 줄이 문장으로 채워지게 구현했습니다.
- 시간 선택은 원형 표현 없이 접근 가능한 범위 입력과 노트 문장으로 표시합니다.
- 마지막 요약은 진단 결과가 아닌 `첫 만남에서 함께 이어 쓸 하루 초안`으로 표현했습니다.
- 연락 신청은 밑줄 입력, 메모 영역과 인덱스 형태로 통일했습니다.
- 완료 화면은 Sage Green `기록 완료` 도장과 접수 메모로 변경했습니다.
- `DayOrbit.tsx`를 제거하고 `RoutineNotebook.tsx`를 추가했습니다.
- 질문 코드와 Google Sheets 스키마는 변경하지 않았습니다.
