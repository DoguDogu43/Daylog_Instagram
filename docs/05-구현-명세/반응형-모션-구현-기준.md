# 데이로그 반응형·모션 구현 기준

## 문서 목적

홈페이지와 LIFE NOTE 신청 경험에 공통으로 적용할 반응형 레이아웃, 상태 유지, 모션, 성능과 접근성 기준을 정의합니다.

이 문서는 다음 외부 참고자료를 데이로그 웹 구현에 맞게 재구성한 적용 문서입니다.

- `구현시_참고자료/모바일 태블릿 PC 주요 뷰포트 정리.md`
- `구현시_참고자료/웹 애니메이션 용어 정리.md`
- `구현시_참고자료/모든 메뉴얼.md`

참고자료 원본은 수정하지 않고 이 문서와 각 구현 명세에서만 데이로그에 맞게 구체화합니다.

## 확정 기술 스택

| 영역 | 기준 |
| --- | --- |
| UI | React |
| 언어 | TypeScript 엄격 모드 |
| 배포 | Vercel |
| 서버 연동 | Vercel Serverless Function을 통한 동일 출처 API |
| 신청 저장 | 통합 Google Apps Script 웹 앱과 Google Sheets |
| 시각 반응 | 접근 가능한 HTML·CSS 기반 LIFE NOTE |

- React 컴포넌트와 훅은 `.tsx`, UI와 무관한 타입·데이터·유틸리티는 `.ts`로 관리합니다.
- `any`를 기본 회피하고 외부 입력은 `unknown`으로 받아 실행 시에 검증합니다.
- 질문 코드, 선택지, 시트 전송 페이로드와 API 응답은 명시적 TypeScript 타입을 공유합니다.
- Apps Script secret과 웹 앱 URL은 Vercel 서버 환경변수에만 두고 React 브라우저 번들에 포함하지 않습니다.
- Next.js, Vite, React Router 등 세부 런타임·라우팅 구성은 구현 시점의 기존 프로젝트 구조를 확인한 후 확정합니다.

## 기본 원칙

- 기기 모델이 아니라 현재 viewport와 콘텐츠가 깨지는 지점에 반응합니다.
- 모바일 우선 1열로 시작하고 충분한 폭이 있을 때만 열을 늘립니다.
- 태블릿을 PC 화면의 축소판으로 구현하지 않습니다.
- 폼, 본문과 예약 흐름은 화면이 넓어도 읽기 편한 폭의 1열을 유지합니다.
- hover는 보조 반응이며 hover 없이도 모든 정보와 기능을 제공합니다.
- 애니메이션은 장식이 아니라 선택, 이동, 완료와 같은 상태 변화를 설명합니다.
- 마룬이는 질문을 대신하거나 답을 유도하지 않고, 장면 진입·전환·완료를 짧은 대화로 안내합니다.

## 반응형 레이아웃

### 대표 설계 프레임

| 우선순위 | 환경 | viewport | 검수 목적 |
| ---: | --- | ---: | --- |
| 1 | 모바일 기본 | `390 × 844` | 주요 사용자 흐름과 CTA |
| 2 | 태블릿 기본 | `820 × 1180` | 터치 크기와 1·2열 전환 |
| 3 | PC 기본 | `1440 × 900` | 최대 콘텐츠 폭과 좌우 배치 |
| 4 | 모바일 최소 | `320 × 568` | 줄바꿈, 키보드와 낮은 화면 |
| 5 | 모바일 대형 | `430 × 932` | 과도한 여백과 하단 도달성 |
| 6 | 태블릿 소형 | `744 × 1133` | 폴드 내부·소형 태블릿 |
| 7 | 태블릿 가로 | `1180 × 820` | PC로 성급히 전환되지 않는지 확인 |
| 8 | 낮은 PC | `1280 × 720` | 고정 UI와 첫 화면 높이 |
| 9 | 넓은 PC | `1920 × 1080` | 콘텐츠 과확장 방지 |

폴더블 지원은 `280 × 653` 외부 화면, `360 × 880` 플립형, `768 × 884` 폴드 내부 화면을 추가로 검수합니다.

### 레이아웃 크기 클래스

| 크기 클래스 | viewport 너비 | 홈페이지 | 신청 경험 |
| --- | ---: | --- | --- |
| Compact | `< 600px` | 1열, 간결한 상단 메뉴 | 1열, 질문 → 시각 반응 순서 |
| Medium | `600~839px` | 1·2열 혼합 | 입력은 1열, 선택 카드는 제한적 2열 |
| Expanded | `840~1279px` | 2열 중심, 터치 밀도 유지 | 질문과 작성 중인 LIFE NOTE 좌우 배치 가능 |
| Desktop | `≥ 1280px` | PC 내비게이션과 다열 구조 | 최대 폭 내 좌우 장면, 폼은 읽기 폭 유지 |

`600px`, `840px`, `1280px`은 초기 전환 기준입니다. 실제 콘텐츠가 깨지는 지점에만 세부 미디어 쿼리를 추가하고 모든 중간 너비를 연속적으로 검수합니다.

### 공통 크기 기준

- 본문은 모바일 `16px` 이상, 태블릿·PC `16~18px`를 기준으로 합니다.
- 버튼과 입력창은 최소 `44px`, 터치 중심 화면에서 `48~56px`를 우선합니다.
- 페이지 좌우 여백은 모바일 `16~20px`, 태블릿 `24~64px`, PC `32px` 이상을 기준으로 유동 조정합니다.
- 본문 중심 콘테이너는 `680~800px`, 일반 서비스 콘테이너는 `960~1280px` 범위에서 설정합니다.
- 글자를 줄여 공간을 만들지 않고, 열 수·여백·장식·문구 길이를 먼저 조정합니다.

## 높이, 키보드와 safe area

- 전체 화면 장면은 `100vh`보다 `100dvh`를 우선합니다.
- 브라우저 UI가 펼쳐진 최소 높이가 중요하면 `100svh`를 보조로 검토합니다.
- 고정 하단 CTA는 `env(safe-area-inset-bottom)`을 포함한 여백을 적용합니다.
- 가상 키보드가 열리면 포커스된 입력과 오류 문구, 다음·제출 버튼에 접근할 수 있어야 합니다.
- 화면 높이가 `480px` 미만이면 고정 헤더와 고정 하단 CTA를 동시에 유지하지 않습니다.

## 폴더블·창 크기 변경

- `280~599px` 외부 화면과 분할 창에서는 모바일 1열을 유지합니다.
- `600~839px` 폴드 내부 화면에서는 1·2열을 콘텐츠에 따라 선택합니다.
- 힌지 위에 질문, 버튼, 입력창과 LIFE NOTE의 작성 내용을 배치하지 않습니다.
- Viewport Segments API와 `device-posture`는 점진적 향상으로만 사용하고 미지원 환경에서도 일반 1·2열이 정상 동작해야 합니다.
- 회전, 접기·펼치기, 분할 창과 리사이즈 후에도 신청 답변, 현재 장면, 포커스와 스크롤 상태를 가능한 범위에서 유지합니다.

## 마룬이 대화형 안내

마룬이가 짧게 말을 건네며 신청 과정을 딱딱한 설문이 아닌 따뜻한 대화로 느끼게 합니다.

- Intro에서 진행 방법과 예상 시간을 안내합니다.
- 장면 전환에서 다음 질문의 맥락을 한 문장으로 연결합니다.
- 완성된 하루 노트가 진단이 아니라 첫 대화의 재료임을 설명합니다.
- 접수 중, 완료, 오류와 재시도 상태를 안내합니다.
- 선택을 평가하는 말·표정·점수·성공음을 사용하지 않습니다.
- 한 장면에서 발화는 원칙적으로 한 번, 두 문장 이내로 제한합니다.
- 대화를 읽지 않아도 질문과 제출을 완료할 수 있어야 합니다.
- 말풍선 전체를 `aria-live`로 자동 낭독하지 않고 중요한 상태만 별도 상태 영역에서 알립니다.

## 모션 명세

### 작성 형식

모션마다 대상, 시작 조건, 시작·완료 상태, 지속 시간, 이징, 반복, 중단 처리, 모션 감소과 성능 기준을 정의합니다. `"부드럽게"`처럼 구현할 수 없는 표현만 사용하지 않습니다.

### 공통 모션 토큰

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `motion-instant` | `100ms` | 모션 감소 페이드·즉시 피드백 |
| `motion-fast` | `140ms` | hover·pressed |
| `motion-base` | `220ms` | 선택·포커스·일반 상태 |
| `motion-medium` | `420ms` | 기록 줄 반응·리빌 |
| `motion-scene` | `700ms` | 장면 전환, 최대 `900ms` |
| `motion-message` | `1200~1800ms` | 짧은 전환 문구, 건너뛰기 가능 |
| `stagger-short` | `60ms` | 카드·문장 순차 등장 |

스태거로 추가되는 총 지연은 `600ms`를 넘지 않습니다.

### 신청 경험 핵심 모션

| 대상 | 시작 조건 | 시작 → 완료 상태 | 시간·이징 | 중단 처리 | 모션 감소 |
| --- | --- | --- | --- | --- | --- |
| 선택 카드 | 선택 | 기본 테두리 → Yellow 테두리·체크 | `220ms`, standard | 새 선택으로 현재 상태에서 전환 | 즉시 상태 교체 |
| LIFE NOTE 기록 줄 | 답변 확정 | 빈 줄 → 선택 내용을 반영한 문장 | `420ms`, standard | 새 답변으로 해당 문장 교체 | 완성 문장 즉시 표시 |
| 질문 장면 | 다음·이전 | 현재 장면 → 다음 장면 | `700ms`, standard | 대기열을 쌓지 않고 도착 상태로 정리 | `100~180ms` 크로스페이드 |
| 전환 문구 | 장면 경계 | 숨김 → 표시 → 숨김 | `1200~1800ms` | 다음 입력 시 즉시 종료 | 생략 또는 즉시 표시 |
| 나의 하루 초안 | 최종 답변 완료 | 흩어진 기록 줄 → 한 장의 완성 노트 | `420~700ms`, standard | CTA 선택 시 완료 상태로 종료 | 정지된 완성 노트 |
| 제출 버튼 | 제출 | 기본 → 처리 중 → 완료·오류 | `140~220ms` | 중복 제출 무시 | 텍스트·아이콘 상태만 변경 |

`standard`는 `cubic-bezier(0.2, 0.8, 0.2, 1)`을 사용합니다.

## 모션 구현·성능

- UI 모션은 `transform`과 `opacity`를 우선합니다.
- 프레임마다 `top`, `left`, `width`, `height`를 변경하지 않습니다.
- 스크롤·포인터 갱신은 `requestAnimationFrame`에 맞추고 필요하면 throttle을 적용합니다.
- `will-change`는 움직이는 요소에 잠시만 적용하고 완료 후 해제합니다.
- 장면이 언마운트되면 이벤트, 타이머, `requestAnimationFrame`과 애니메이션을 정리합니다.
- 카드와 이미지의 공간을 미리 확보해 레이아웃 이동을 방지합니다.
- 저사양 모바일에서 선택 반응과 폼 입력이 모션보다 우선합니다.

## 모션 감소·정지 대체

- `prefers-reduced-motion: reduce`에서 큰 이동, 회전, 패럴랙스와 반복 루프를 제거합니다.
- 상태 변화는 색상, 테두리, 아이콘과 텍스트로 즉시 표시합니다.
- 모션이 없어도 동일한 질문, 답변, 하루 노트와 제출 결과를 제공합니다.
- 자동 전환 문구는 건너뛰기 수단을 제공하거나 모션 감소 설정에서 생략합니다.

## 폼과 React 상태 유지

- 하나의 상태 원본을 유지하고 레이아웃 전환으로 컴포넌트 트리가 불필요하게 재생성되지 않게 합니다.
- viewport 변경이 질문 장면 이동을 일으키거나 답변을 초기화하지 않습니다.
- 제출 중 화면을 회전하거나 창 크기를 바꾸어도 중복 요청이 생성되지 않습니다.
- 뒤로 가기 후 답변을 바꾸면 이후 요약과 LIFE NOTE의 해당 문장을 즉시 다시 작성합니다.
- 오프라인·시간 초과·서버 오류를 구분하고 재시도해도 같은 `requestId`를 유지합니다.

## 권장 검수 순서

1. `320 × 568`에서 신청 시작부터 제출까지 완료합니다.
2. `390 × 844`에서 기본 장면, 모션과 하단 CTA를 검수합니다.
3. `820 × 1180`과 `1180 × 820`에서 1·2열 전환과 터치 크기를 확인합니다.
4. `1280 × 720`과 `1440 × 900`에서 낮은 화면과 PC 좌우 배치를 확인합니다.
5. 폴더블을 지원하면 `280 × 653`, `360 × 880`, `768 × 884`를 검수합니다.
6. 대표 브라우저에서 200% 확대, 키보드 전체 흐름과 모션 감소를 검수합니다.
7. 느린 연결, 오프라인, 시간 초과와 재시도에서 입력과 접수번호가 유지되는지 확인합니다.
