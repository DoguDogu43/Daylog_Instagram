# 디자인 및 구현 검수 체크리스트

## 사용 방법

홈페이지와 리플렛을 제작하면서 항목별로 확인합니다. 미확정 정보는 임의로 채우지 않고 담당자와 확정한 뒤 완료로 표시합니다.

## 0. 구현 환경

- [ ] UI가 React와 TypeScript 엄격 모드로 빌드된다.
- [ ] 외부 입력과 API 응답에 실행 시 검증이 있고 `any`로 우회하지 않는다.
- [ ] Vercel Preview에서 신청 전체 흐름을 검수한 후 Production으로 승격한다.
- [ ] Apps Script URL과 secret이 React 브라우저 번들에 포함되지 않는다.

## 1. 브랜드

- [ ] 회사명, 브랜드명, 서비스명과 마룬이의 관계가 명확하다.
- [ ] 대표 메시지가 한 가지 중심 문장으로 정리되어 있다.
- [ ] 신뢰감, 성장과 따뜻함이 함께 느껴진다.
- [ ] 상담센터, 자기계발 학원 또는 이벤트 업체처럼 보이지 않는다.
- [ ] 고객을 평가하거나 의지 부족으로 표현하는 문구가 없다.
- [ ] 코치가 정답을 가르치는 사람처럼 표현되지 않는다.

## 2. 컬러

- [ ] Deep Navy, Growth Yellow와 Warm Ivory가 핵심 조합으로 보인다.
- [ ] 홈페이지의 시각적 비중이 대체로 Ivory 70%, Navy 20%, Yellow 10%에 가깝다.
- [ ] Sage Green은 성장과 변화 결과 영역에 제한적으로 사용했다.
- [ ] Warm Ivory 위에 Growth Yellow 작은 글자를 사용하지 않았다.
- [ ] Sage Green 위에 흰색 일반 본문을 사용하지 않았다.
- [ ] Primary CTA는 Growth Yellow 배경과 Deep Navy 텍스트를 사용한다.
- [ ] 디자인 시스템에 없는 유사 색상을 임의로 추가하지 않았다.

## 3. 타이포그래피

- [ ] 공식 한글·영문 서체와 사용 권한이 확인되었다.
- [ ] H1은 페이지당 하나다.
- [ ] 제목 단계가 순서대로 구성되어 있다.
- [ ] 모바일에서도 제목 줄바꿈이 어색하지 않다.
- [ ] 본문 줄 길이와 행간이 읽기 편하다.
- [ ] 강조 효과를 지나치게 중첩하지 않았다.

## 4. Hero

- [ ] 남녀 마룬이의 역할과 공식 표기가 확정되었다.
- [ ] 정장 이미지가 전문적이지만 권위적으로 보이지 않는다.
- [ ] Hero 대표 문구가 하나로 확정되었다.
- [ ] `하루` 또는 `설계합니다`의 노란 밑줄이 글자를 가리지 않는다.
- [ ] Primary CTA 문구와 실제 동작이 일치한다.
- [ ] 모바일에서 얼굴, 손과 주요 자세가 잘리지 않는다.
- [ ] 이미지 대체 텍스트가 적절하다.

## 5. 홈페이지 콘텐츠

- [ ] 데이로그가 루틴표를 제공하는 업체가 아니라는 점이 첫 화면에서 이해된다.
- [ ] 직접 만남과 대화가 핵심이라는 점이 드러난다.
- [ ] 서비스 흐름이 만남, 실행, 다시 만남의 반복으로 설명된다.
- [ ] Life Session과 Life Interview가 혼동되지 않는다.
- [ ] 코치 역할과 서비스 범위가 명확하다.
- [ ] 가격, 장소, 운영 시간과 예약 방법이 최신 정보다.
- [ ] 임시 문구와 빈 링크가 남아 있지 않다.

## 6. 반응형

- [ ] `320 × 568`, `390 × 844`, `430 × 932`에서 핵심 흐름을 완료할 수 있다.
- [ ] 작은 화면에서 세로 스크롤을 자연스럽게 사용할 수 있고 페이지·노트 내부에 불필요한 이중 스크롤이 없다.
- [ ] 모든 대표 모바일 너비에서 가로 스크롤, 텍스트 잘림과 CTA 잘림이 없다.
- [ ] `820 × 1180`, `1180 × 820`에서 UI가 PC 축소판처럼 작아지지 않는다.
- [ ] `1280 × 720`, `1440 × 900`, `1920 × 1080`에서 낮은 높이와 콘텐츠 과확장을 확인했다.
- [ ] `280px`의 폴더블 외부 화면을 지원 범위에 포함한다면 핵심 기능과 문구가 잘리지 않는다.
- [ ] `599 → 600px`, `839 → 840px`, `1279 → 1280px` 경계에서 열 수와 UI 밀도가 자연스럽게 바뀐다.
- [ ] 모든 중간 너비를 연속적으로 변경해도 가로 스크롤과 급격한 크기 변화가 없다.
- [ ] 모바일 CTA 터치 영역이 44×44px 이상이다.
- [ ] 태블릿에서 카드와 내비게이션이 과도하게 좁아지지 않는다.
- [ ] 데스크톱에서 본문 줄이 지나치게 길어지지 않는다.
- [ ] 서비스 흐름이 모바일에서 자연스러운 세로 순서로 바뀐다.
- [ ] `844 × 390` 가로 모바일에서 고정 헤더와 하단 CTA가 내용을 동시에 가리지 않는다.
- [ ] 200% 확대과 큰 글자에서 정보 손실, 겹침과 버튼 잘림이 없다.
- [ ] 회전, 창 크기 변경과 폴더블 접기·펼치기 후에도 현재 페이지·답변·스크롤 상태가 유지된다.
- [ ] 노치, 홈 인디케이터와 폴더블 힌지 영역에 핵심 UI가 겹치지 않는다.

## 7. 상호작용

- [ ] 모든 링크와 버튼이 실제 동작한다.
- [ ] 모바일 메뉴를 키보드로 열고 닫을 수 있다.
- [ ] 모바일 메뉴를 `Escape` 키로 닫을 수 있다.
- [ ] 외부 예약 페이지 이동이 명확하다.
- [ ] 폼의 로딩, 성공, 오류와 중복 제출 상태가 구현되어 있다.
- [ ] 애니메이션이 콘텐츠 읽기를 방해하지 않는다.
- [ ] 모션 감소 설정에서 장식 애니메이션이 제거된다.
- [ ] 모션 명세에 트리거, 시작·완료 상태, 시간, 이징, 중단과 정지 대체가 정의되어 있다.
- [ ] 연속 클릭·스크롤 중에도 애니메이션이 중간 상태에 멈추거나 대기열에 쌓이지 않는다.
- [ ] 모션은 `transform`과 `opacity`를 우선하고 언마운트 시 이벤트·타이머·관찰자를 정리한다.

## 8. 접근성

- [ ] HTML 문서 언어가 한국어로 지정되어 있다.
- [ ] 키보드만으로 모든 기능을 사용할 수 있다.
- [ ] 포커스 표시가 모든 인터랙션 요소에서 보인다.
- [ ] 색상 외에도 텍스트나 형태로 정보를 구분한다.
- [ ] 의미 있는 이미지에 대체 텍스트가 있다.
- [ ] 장식 이미지는 보조 기술에서 제외된다.
- [ ] 폼 입력에 연결된 라벨과 오류 메시지가 있다.
- [ ] 본문과 버튼의 명도 대비가 WCAG AA 이상이다.

## 9. 신청 경험

- [ ] 첫 화면에서 평범한 설문이 아니라 데이로그의 브랜드 경험이라는 인상을 준다.
- [ ] Intro부터 완료까지 나만의 노트와 메모장 메타포가 일관되게 이어진다.
- [ ] 답변할 때 선택 카드, 텍스트 입력과 오류 상태가 즉시 반응한다.
- [ ] 생활 탐색은 4단계이며 에너지 순간 두 항목 외의 필수 자유 입력 없이 약 3분 안에 완료할 수 있다.
- [ ] `comfortableTime`과 `difficultTime`은 각각 앞뒤 공백을 제거한 1~100자 문자열이다.
- [ ] 4단계의 생활 영역은 누른 순서대로 1·2·3순위가 되고 선택 취소 시 순위가 당겨진다.
- [ ] 이름, 나이, `010-0000-0000` 형식 전화번호, 주변 역, 인터뷰 가능 요일·시간대와 개인정보 동의가 신청 필수값이다.
- [ ] 노트 장식이 질문, 입력, 오류와 CTA를 가리거나 뒤로 밀지 않는다.
- [ ] 선택 상태를 색상뿐 아니라 아이콘과 텍스트로도 구분한다.
- [ ] 단계 전환이 600~900ms 안에 끝나며 건너뛸 수 있다.
- [ ] 장면 전환 후 새 질문 제목으로 포커스가 이동한다.
- [ ] 모션 감소 설정에서 회전과 이동이 짧은 페이드로 대체된다.
- [ ] 4단계 완료 뒤 LIFE SESSION 안내를 확인하고 신청 정보 입력으로 이동한다.
- [ ] `togetherStyle` 질문이나 요약 화면이 사용자 문구와 뒤로 가기에 남아 있지 않다.
- [ ] 민감한 답변이 URL, 분석 이벤트나 브라우저 영구 저장소에 포함되지 않는다.
- [ ] 상세한 생활 정보보다 예약에 필요한 최소 정보만 온라인에서 수집한다.
- [ ] 제출 오류가 발생해도 이전 선택 내용이 유지된다.
- [ ] 가상 키보드가 열려도 현재 입력, 오류 문구와 제출 버튼에 접근할 수 있다.
- [ ] 화면 회전과 viewport 변경이 질문 단계를 이동시키거나 접수번호를 재생성하지 않는다.
- [ ] 마룬이 대화를 생략해도 모든 질문과 제출을 완료할 수 있다.
- [ ] 마룬이가 선택을 평가하거나 정답을 유도하는 말·표정·성공음을 사용하지 않는다.

## 10. Google Sheets 연동

- [ ] 브라우저 번들과 공개 환경변수에 secret이 포함되지 않는다.
- [ ] 브라우저는 Apps Script가 아니라 동일 출처 Vercel API로 요청한다.
- [ ] `formType`이 `daylog_life_session`으로 전달된다.
- [ ] `schemaVersion`이 `daylog-life-session-v3`이며 프론트, Vercel API와 Apps Script가 같은 계약을 검증한다.
- [ ] Apps Script 스크립트 속성에 `DAYLOG_LIFE_SESSION_SECRET`이 등록되어 있다.
- [ ] Apps Script 프로젝트의 `doGet()`과 `doPost()`이 각각 하나다.
- [ ] `DaylogLifeSession.gs`가 공통 함수를 중복 선언하지 않는다.
- [ ] 신청 데이터가 데이로그 신청응답 탭에만 저장된다.
- [ ] 퍼널 데이터가 데이로그 퍼널이벤트 탭에만 저장된다.
- [ ] 같은 접수번호를 다시 보내도 신청 행이 중복되지 않는다.
- [ ] 같은 이벤트 ID를 다시 보내도 이벤트 행이 중복되지 않는다.
- [ ] 사용자 입력이 Sheets 수식으로 실행되지 않는다.
- [ ] 신청 응답에 표시 문구와 코드 JSON이 함께 저장된다.
- [ ] 퍼널 이벤트에 이름, 연락처와 생활 답변이 포함되지 않는다.
- [ ] 퍼널 단계에서 `change_area_selected` 다음 `session_info_viewed`, `application_started`가 이어진다.
- [ ] 신청응답 탭이 v3 23열 구조이며 신청 필드와 변화 영역 순위를 저장한다.
- [ ] 기존 v1 탭의 `함께하는 방식`은 보관 필드명으로 바뀌고 과거 값이 보존된다.
- [ ] 기존 탭에는 누락된 v3 열만 추가되고 기존 데이터는 보존된다.
- [ ] Apps Script 수정 후 새 웹 앱 버전을 배포했다.
- [ ] 기존 다섯 폼의 신청과 퍼널 집계를 회귀 테스트했다.

## 11. 성능

- [ ] Hero 이미지가 화면별 적절한 크기로 제공된다.
- [ ] 화면 아래 이미지는 지연 로드된다.
- [ ] 이미지 너비, 높이 또는 종횡비가 지정되어 있다.
- [ ] 사용하지 않는 스크립트와 스타일이 제거되었다.
- [ ] 필요한 서체 굵기만 로드한다.
- [ ] 실제 모바일 네트워크에서 초기 화면을 점검했다.
- [ ] Core Web Vitals를 확인했다.
- [ ] 저사양 모바일에서 카드 선택과 입력 반응이 모션보다 우선한다.
- [ ] 시각 자산의 영역을 미리 확보해 로딩과 모션 중 레이아웃 이동이 없다.

## 12. SEO와 공유

- [ ] 페이지 제목과 설명이 설정되어 있다.
- [ ] Open Graph 제목, 설명과 이미지가 설정되어 있다.
- [ ] 공유 이미지의 텍스트와 얼굴이 잘리지 않는다.
- [ ] 공개 주소의 canonical URL이 설정되어 있다.
- [ ] 사이트맵과 검색 엔진 노출 정책이 설정되어 있다.
- [ ] 푸터의 회사 및 연락 정보가 정확하다.

## 13. 개인정보와 예약

- [ ] 신청에 꼭 필요한 정보만 수집한다.
- [ ] 수집 목적과 보관 기간을 안내한다.
- [ ] 개인정보 동의 절차가 준비되어 있다.
- [ ] 외부 예약 도구의 개인정보 처리 조건을 확인했다.
- [ ] 예약 시작부터 완료까지 실제로 테스트했다.
- [ ] 고객의 민감한 생활 정보를 공개 폼에서 과도하게 요구하지 않는다.

## 14. 리플렛

- [ ] 판형, 양면·접지 방식과 인쇄 수량이 확정되었다.
- [ ] 인쇄소의 도련과 안전 영역 규격을 반영했다.
- [ ] CMYK 변환 후 실물 색상을 교정했다.
- [ ] 마룬이 원본이 최종 크기 기준 300ppi 이상이다.
- [ ] QR 코드를 실제 인쇄 크기로 테스트했다.
- [ ] 장소, 시간, 비용, URL과 연락처가 최신 정보다.
- [ ] 작은 본문을 실물 출력물에서 읽을 수 있다.
- [ ] 웹과 리플렛의 핵심 문구와 컬러가 일치한다.
