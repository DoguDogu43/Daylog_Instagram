# 데이로그 신청 경험 구현 명세

> 현재 UI 기준은 [신청폼 카드 기반 라이트 리디자인 기획](../04-디자인/신청-폼-카드-기반-라이트-리디자인-기획.md)입니다. 기존 LIFE NOTE의 물리적 노트 표현은 더 이상 구현하지 않습니다.

## 구현 목표

[카드 기반 라이트 리디자인](../04-디자인/신청-폼-카드-기반-라이트-리디자인-기획.md)을 접근 가능하고 반응형인 웹 인터페이스로 구현합니다.

고객이 설문을 작성한다는 인상보다 지금의 하루를 한 줄씩 기록한다는 인상을 받아야 합니다. 질문 단계에서는 질문과 선택에 집중하고, 4단계가 끝나면 LIFE SESSION 안내를 확인한 뒤 신청 정보를 입력합니다.

명확한 카드 위계와 넉넉한 여백으로 사용자가 현재 질문과 다음 행동에 집중할 수 있어야 합니다.

## 신청 편의 구현 원칙

- 생활 탐색은 4개 질문, 전체 약 3분을 목표로 합니다.
- 에너지 순간은 각각 1~100자의 짧은 자유 텍스트로 받으며 나머지 생활 탐색은 선택형입니다.
- 단일 선택은 카드 전체를 눌러 선택할 수 있게 하고 선택 후 다음 CTA를 즉시 사용할 수 있게 합니다.
- 다음 CTA는 선택 전 비활성 상태를 명확히 표시하고 선택 후 화면 안에서 바로 찾을 수 있어야 합니다.
- 신청의 필수 입력은 `displayName`, `age`, `phoneNumber`, `nearbyStation`, `preferredDays`, `preferredPeriods`, `privacyConsent`입니다.
- 전화번호는 `010-0000-0000` 형식으로 자동 정리하고 프론트와 서버에서 같은 형식을 검증합니다.
- 필수와 선택을 시각적 레이블과 접근 가능한 설명으로 구분합니다.
- 첫 오류는 해당 입력 가까이에 표시하고 오류 입력으로 포커스를 이동합니다.
- 제출 실패, 새로고침 전 이동과 이전 단계 이동에서도 작성한 생활 답변을 유지합니다.

## 기술 구성

- React 19
- TypeScript 엄격 모드
- Vite
- Vercel 배포
- Vercel Serverless Function
- 통합 Google Apps Script와 Google Sheets
- 외부 UI·모션 라이브러리 없는 CSS 중심 구현

## 구현 범위

- 카드형 라이트 인트로
- 4개 생활 탐색 질문
- 연락·희망 일정 신청
- 제출 성공과 오류 상태
- 모바일·태블릿·데스크톱 반응형
- 키보드, 스크린 리더와 모션 감소 설정
- Vercel API 입력 검증과 Google Sheets 중계

## 카드 기반 시각 구조

### 전체 캔버스

- 전체 배경은 밝은 회백색, 핵심 콘텐츠는 흰색 카드로 구성합니다.
- 기본 본문 폭은 560px, 연락 신청 화면은 최대 720px입니다.
- 4개 질문 단계는 상단 4분할 진행 바로 표시하고 프로그램·연락 단계는 텍스트 단계로 안내합니다.
- 그림자와 라운드는 정보 계층을 구분하는 수준으로만 사용합니다.
- 스프링, 포스트잇, 종이 가로줄, 붉은 여백선과 페이지 넘김 장식은 사용하지 않습니다.

### 답변 표시

질문 화면에 답변을 반복하는 실시간 노트를 렌더링하지 않으며 별도 최종 요약도 제공하지 않습니다. 사용자가 선택한 생활 답변은 신청 데이터로 안전하게 전달하고, 화면에는 현재 질문과 다음 행동을 우선 표시합니다.

### 그래픽 원칙

- 사진과 래스터 텍스처를 사용하지 않습니다.
- 상태 아이콘은 CSS 또는 텍스트 기호로 단순하게 구현합니다.
- 카드에 임의의 회전을 주지 않습니다.

## 질문과 선택

### 선택 카드

- 실제 `input[type="radio"]` 또는 `input[type="checkbox"]`를 사용합니다.
- 카드 전체를 `label`로 연결합니다.
- 기본 상태는 흰색 또는 연한 중립색 카드입니다.
- 선택 상태는 체크, Growth Yellow 배경과 진한 테두리를 함께 사용합니다.
- Hover보다 키보드 Focus 상태를 더 명확하게 표시합니다.

### 에너지 순간 입력

- `comfortableTime`과 `difficultTime`을 접근 가능한 텍스트 입력으로 받습니다.
- 앞뒤 공백을 제거한 1~100자 문자열만 허용합니다.
- 빠른 입력 예시 칩을 제공할 수 있으나 직접 입력을 제한하지 않습니다.
- 두 값이 같다는 이유만으로 임의로 거부하지 않습니다.

### 변화 영역

- 1~3개까지 선택하며 누른 순서를 1·2·3순위로 저장합니다.
- 선택을 취소하면 뒤 순위가 자동으로 당겨지고, 다시 선택하면 마지막 순위로 들어갑니다.
- 최대 개수를 넘으면 기존 선택을 유지하고 오류를 안내합니다.

## 인트로

- 대표 문장, 짧은 설명, 3개의 핵심 정보 카드와 CTA를 세로 흐름으로 배치합니다.
- 코치와 인물 이미지를 렌더링하지 않습니다.
- CTA는 `내 하루 적고 신청하기`이며 질문 수를 안내할 때는 `4개의 짧은 기록 · 약 3분`처럼 현재 흐름과 일치시킵니다.
- `3분간 하루를 기록하고 60분 오프라인 LIFE SESSION을 신청합니다.`라는 목적을 CTA 전에 표시합니다.
- 시작 전 카드에는 질문 수, 예상 시간, 세션 신청이라는 구체적인 정보만 보여주며 진단 결과처럼 보이는 내용을 넣지 않습니다.

## 질문 완료 후 프로그램 안내

- 4단계 완료 뒤 별도 답변 요약 장면은 만들지 않고 LIFE SESSION 설명 페이지로 이동합니다.
- 안내 페이지에는 60분 오프라인 1:1 프로그램의 다섯 구간과 일주일 뒤 후속 만남을 표시합니다.
- 프로그램을 확인한 뒤 신청 정보 입력으로 이동합니다.
- 점수, 등급, 성격 유형과 자동 해석을 만들지 않습니다.
- 신청 데이터와 퍼널 단계는 `daylog-life-session-v3` 기준을 따릅니다.

## 연락 신청

- 연락 신청은 기본 정보, 희망 일정, 개인정보 동의의 3개 카드로 구성합니다.
- 이름, 나이, 전화번호, 거주지 주변 역, 인터뷰 가능 요일·시간대와 개인정보 동의를 필수로 검증합니다.
- 연락 수단은 전화 또는 문자로 고정하며 다른 연락 방법을 수집하지 않습니다.
- 한 줄 입력은 테두리가 있는 표준 입력 상자로 표시합니다.
- 인터뷰 가능 요일과 시간대는 44px 이상의 선택 칩으로 표시합니다.
- 개인정보 안내에는 실제 수집 항목, 수집 목적과 신청일로부터 3개월의 보유 기간을 표시합니다.
- 개인정보 동의는 별도 카드 안에 표시합니다.
- 신청 개인정보는 브라우저 저장소에 보관하지 않습니다.

## 완료 화면

- `기록 완료` 문구와 체크를 Sage Green 원형 상태로 표시합니다.
- 접수번호는 영수증형 정보 행으로 표시하고 복사 버튼을 제공합니다.
- 완료 후 생활 답변의 `sessionStorage` 값을 제거합니다.
- 다시 시작하면 질문, 연락 정보, 화면 상태, `sessionId`와 `requestId`를 모두 새로 초기화합니다.

## 반응형

| 크기 | 구현 방식 |
| --- | --- |
| `< 600px` | 질문 중앙 단일 열, 일반 선택 1열과 생활 영역 2열 |
| `< 600px`, 높이 `≤ 700px` | 생활 영역만 제목 중심 3열로 압축 |
| `600~839px` | 질문 중앙 단일 열, 선택 카드 2열 허용 |
| `≥ 840px` | 최대 560px 중앙 질문, 연락 신청 최대 720px와 2열 기본 정보 |

대표 검수 크기:

- `320 × 568`
- `390 × 844`
- `820 × 1180`
- `1440 × 900`
- `1920 × 1080`

구현 기준:

- `100dvh`를 우선하되 콘텐츠를 한 화면 높이에 억지로 맞추지 않습니다.
- 모바일 키보드가 입력과 제출 버튼을 가리지 않게 고정 CTA를 사용하지 않습니다.
- 화면 크기가 바뀌어도 답변과 현재 단계가 초기화되지 않습니다.
- 작은 화면에서는 질문과 입력을 먼저 보이게 합니다.
- 모바일에서는 자연스러운 세로 스크롤을 허용하고 가로 잘림과 입력 가림 방지를 우선합니다.

## 모션

| 요소 | 시간 | 역할 |
| --- | ---: | --- |
| 선택 상태 | 140~180ms | 체크, 배경과 테두리 반영 |
| 화면 전환 | 360ms | 다음 페이지 이동 |
| CTA Hover | 140ms | 배경과 그림자 변화 |

- 반복 회전과 무한 장식 모션은 사용하지 않습니다.
- `transform`과 `opacity`를 우선합니다.
- 모션 감소 설정에서는 모든 전환을 1ms 수준으로 줄입니다.
- 애니메이션이 없어도 선택과 진행 상태를 이해할 수 있어야 합니다.

## 접근성

- 각 질문은 `fieldset`과 `legend`로 묶습니다.
- 장면 전환 후 질문 H1으로 포커스를 이동합니다.
- 현재 단계는 텍스트 대체가 있는 진행률로 제공합니다.
- 카드의 시각적 입력을 숨겨도 실제 폼 입력은 유지합니다.
- 오류는 `role="alert"`와 `aria-live="polite"`로 전달합니다.
- 모든 터치 대상은 최소 44×44px을 유지합니다.
- 색상뿐 아니라 체크, 문장과 테두리로 상태를 구분합니다.
- 장식 아이콘은 스크린 리더에서 숨기고 의미는 텍스트로 제공합니다.

## 상태와 데이터 보관

- 생활 탐색 답변만 `sessionStorage`에 임시 저장합니다.
- 신청 개인정보는 React 메모리 상태에만 둡니다.
- 접수번호와 세션 ID는 화면 세션 동안 유지합니다.
- 질문 답변, 이름과 연락처를 URL에 넣지 않습니다.
- 제출 완료 시 임시 생활 답변을 삭제합니다.
- `schemaVersion`은 `daylog-life-session-v3`를 사용합니다.

데이터 코드와 Google Sheets 열은 [신청 폼 데이터 정의](신청-폼-데이터-정의.md)를 따릅니다.

## Google Sheets 연동

- 브라우저는 같은 출처의 Vercel API로만 전송합니다.
- Vercel API가 입력을 재검증하고 서버 비밀값을 추가합니다.
- 최종 신청은 `/api/daylog/application`으로 전송합니다.
- 개인정보 없는 퍼널 이벤트는 `/api/daylog/track`으로 전송합니다.
- 통합 Apps Script는 `daylog_life_session` 처리기로 라우팅합니다.
- 접수번호와 이벤트 ID로 중복 저장을 막습니다.

상세 구조는 [Google Sheets 연동 설계](신청-폼-Google-Sheets-연동.md)를 따릅니다.

## 성능

- 첫 화면에 사진, 영상과 외부 폰트를 추가하지 않습니다.
- 카드, 진행 바와 완료 체크는 CSS로 구현합니다.
- 불필요한 모션 라이브러리를 설치하지 않습니다.
- 시각 상태 변경이 레이아웃 전체를 다시 계산하지 않게 합니다.
- 모바일에서도 선택 반응이 즉시 보여야 합니다.

## 분석 이벤트

단계 코드는 4단계 질문, 프로그램 안내와 신청 흐름에 맞춥니다.

| 단계 코드 | UI 의미 |
| --- | --- |
| `started` | 생활 탐색 시작 |
| `daily_rhythm_selected` | 오늘의 리듬 기록 |
| `energy_selected` | 편안한·버거운 순간 기록 |
| `past_pattern_selected` | 지속 방식 기록 |
| `change_area_selected` | 변화 영역 기록 |
| `session_info_viewed` | 프로그램 안내 확인 |
| `application_started` | 신청 정보 입력 시작 |
| `consent_accepted` | 개인정보 동의 |
| `submitted` | 신청 완료 |

퍼널 이벤트에 답변 내용과 개인정보를 포함하지 않습니다.

- [x] 코치와 인물 이미지 없이 브랜드 인상이 유지됩니다.
- [ ] 키보드와 스크린 리더만으로 완료할 수 있습니다.
- [x] 280px과 320px 너비에서 입력, 문구와 CTA가 가로로 잘리거나 겹치지 않습니다.
- [ ] 모바일 세로 스크롤 중 가상 키보드가 현재 입력과 제출 CTA 접근을 막지 않습니다.
- [ ] 모션 감소 설정에서 의미가 손실되지 않습니다.
- [ ] 개인정보가 URL, 퍼널 이벤트와 브라우저 저장소에 남지 않습니다.
- [x] 빌드, 린트와 자동화 테스트가 통과합니다.
