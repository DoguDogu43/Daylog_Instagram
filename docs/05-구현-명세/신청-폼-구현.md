# 데이로그 신청 경험 구현 명세

## 구현 목표

[신청 경험 디자인](../04-디자인/신청-폼-디자인.md)의 `LIFE NOTE` 경험을 접근 가능하고 반응형인 웹 인터페이스로 구현합니다.

고객이 설문을 작성한다는 인상보다 지금의 하루를 한 줄씩 기록한다는 인상을 받아야 합니다. 질문 단계에서는 질문과 선택에 집중하고, 선택한 답변은 마지막에 `나의 하루 초안`으로 정리됩니다.

노트 메타포는 신청을 더 쉽게 이해하게 해야 하며 입력 단계나 장식 요소를 늘리는 이유가 되어서는 안 됩니다.

## 신청 편의 구현 원칙

- 생활 탐색은 5개 질문, 전체 약 3분을 목표로 합니다.
- 생활 탐색 단계에는 필수 자유 입력을 추가하지 않습니다.
- 단일 선택은 카드 전체를 눌러 선택할 수 있게 하고 선택 후 다음 CTA를 즉시 사용할 수 있게 합니다.
- 다음 CTA는 선택 전 비활성 상태를 명확히 표시하고 선택 후 화면 안에서 바로 찾을 수 있어야 합니다.
- 연락 신청의 필수 입력은 `displayName`, `contactMethod`, `contactValue`, `privacyConsent`로 제한합니다.
- `preferredDays`, `preferredPeriods`, `additionalNote`는 선택 입력으로 처리합니다.
- 필수와 선택을 시각적 레이블과 접근 가능한 설명으로 구분합니다.
- 첫 오류는 해당 입력 가까이에 표시하고 오류 입력으로 포커스를 이동합니다.
- 제출 실패, 새로고침 전 이동과 이전 단계 이동에서도 작성한 생활 답변을 유지합니다.

## 기술 구성

- React 19
- TypeScript 엄격 모드
- Vite
- Vercel 배포
- Vercel Serverless Function
- 통합 Google Apps Script와 Google Sheets
- 외부 UI·모션 라이브러리 없는 CSS 중심 구현

## 구현 범위

- 노트형 인트로
- 5개 생활 탐색 질문
- 선택 내용을 정리한 최종 하루 노트
- 하루 노트 요약
- 연락·희망 일정 신청
- 제출 성공과 오류 상태
- 모바일·태블릿·데스크톱 반응형
- 키보드, 스크린 리더와 모션 감소 설정
- Vercel API 입력 검증과 Google Sheets 중계

## 노트 시각 구조

### 전체 캔버스

- 바깥 배경은 Deep Navy 책상 톤입니다.
- 내부 전체는 Warm Ivory 노트 종이입니다.
- CSS `repeating-linear-gradient`로 옅은 가로줄을 만듭니다.
- 왼쪽 세로 여백선은 낮은 채도의 붉은 선으로 표시합니다.
- 화면 왼쪽의 반복 제본 표시는 장식이며 포인터 입력을 방해하지 않습니다.

### 최종 노트

다음 항목을 텍스트 목록으로 렌더링합니다.

1. 오늘의 리듬
2. 편안한 시간
3. 버거운 시간
4. 계속할 수 있었던 방식
5. 먼저 바꾸고 싶은 곳
6. 함께하고 싶은 방식

질문 화면에서는 이 목록을 렌더링하지 않습니다. 마지막 요약에서 선택한 답변을 다음 상태로 보여줍니다.

- 빈 번호 상자가 체크 표시로 변경
- 문장 색상이 옅은 회색에서 Deep Navy로 변경
- 문장 아래에 Growth Yellow 형광펜 효과 적용

노트는 시각 장식으로만 숨기지 않고 `article`, `dl`, `dt`, `dd` 구조를 사용해 보조 기술에서도 읽을 수 있게 합니다.

### 종이 겹침과 테이프

- 종이 뒤 한 장은 의사 요소로 구현합니다.
- 테이프는 반투명 Growth Yellow 사각형으로 구현합니다.
- 사진, 래스터 텍스처와 인라인 SVG는 사용하지 않습니다.
- 기울기는 1~2도 이내로 제한합니다.

## 질문과 선택

### 선택 카드

- 실제 `input[type="radio"]` 또는 `input[type="checkbox"]`를 사용합니다.
- 카드 전체를 `label`로 연결합니다.
- 기본 상태는 빈 메모지와 가로줄입니다.
- 선택 상태는 체크, 노란 메모 배경과 종이 그림자를 함께 사용합니다.
- Hover보다 키보드 Focus 상태를 더 명확하게 표시합니다.

### 시간 선택

- 미선택 상태가 있는 접근 가능한 `select` 두 개를 사용합니다.
- 0~23 사이의 정수 시간을 입력합니다.
- 출력값은 노란 메모 조각처럼 표시합니다.
- 편안한 시간과 힘든 시간이 같으면 다음 단계로 이동하지 않습니다.
- 시간 선택과 무관한 장식용 드래그 UI를 사용하지 않습니다.

### 변화 영역

- 1~3개까지 선택합니다.
- 선택한 영역 중 첫 번째로 다룰 하나를 별도로 선택합니다.
- 최대 개수를 넘으면 기존 선택을 유지하고 오류를 안내합니다.

## 인트로

- 왼쪽은 큰 대표 문장과 CTA입니다.
- 오른쪽은 실제 입력 전의 빈 노트 예시입니다.
- 코치와 인물 이미지를 렌더링하지 않습니다.
- CTA는 `내 하루 적고 신청하기`, 보조 문구는 `5개의 짧은 선택 · 약 3분`입니다.
- `3분간 하루를 기록하고 60분 오프라인 LIFE SESSION을 신청합니다.`라는 목적을 CTA 전에 표시합니다.
- 시작 전 노트에는 구체적인 기록 힌트만 보여주며 진단 결과처럼 보이는 내용을 넣지 않습니다.

## 하루 노트 요약

- 고객이 직접 선택한 문장만 정리합니다.
- 점수, 등급, 성격 유형과 자동 해석을 만들지 않습니다.
- `첫 만남에서 함께 이어 쓸 하루 초안`임을 명확하게 안내합니다.
- 답변을 수정하면 완료 노트도 다시 계산합니다.
- 기존 Google Sheets 필드 코드와 퍼널 단계 코드는 변경하지 않습니다.

## 연락 신청

- 연락 신청도 같은 종이와 메모 세계관을 유지합니다.
- 이름·호칭, 연락 방법, 연락처와 개인정보 동의만 필수로 검증합니다.
- 희망 요일, 희망 시간대와 추가 이야기는 비워둔 채 제출할 수 있습니다.
- 한 줄 입력은 밑줄형으로 표시합니다.
- 추가 이야기는 가로줄이 있는 메모 영역으로 표시합니다.
- 희망 요일과 시간대는 인덱스 탭 같은 직각 칩으로 표시합니다.
- 개인정보 동의는 노란 메모지 안에 표시합니다.
- 이름과 연락처는 브라우저 저장소에 보관하지 않습니다.

## 완료 화면

- `기록 완료` 문구와 체크를 Sage Green 도장 형태로 표시합니다.
- 접수번호는 노란 보관 메모 형태로 표시합니다.
- 완료 후 생활 답변의 `sessionStorage` 값을 제거합니다.
- 다시 시작하면 질문, 연락 정보와 화면 상태를 초기화합니다.

## 반응형

| 크기 | 구현 방식 |
| --- | --- |
| `< 600px` | 질문 중앙 단일 열, 일반 선택 1열과 생활 영역 2열 |
| `< 600px`, 높이 `≤ 700px` | 생활 영역만 제목 중심 3열로 압축 |
| `600~839px` | 질문 중앙 단일 열, 선택 카드 2열 허용 |
| `≥ 840px` | 최대 1040px 안의 중앙 질문과 2열 선택 카드 |

대표 검수 크기:

- `320 × 568`
- `390 × 844`
- `820 × 1180`
- `1440 × 900`
- `1920 × 1080`

구현 기준:

- `100dvh`를 우선합니다.
- 모바일 키보드가 입력과 제출 버튼을 가리지 않게 고정 CTA를 사용하지 않습니다.
- 화면 크기가 바뀌어도 답변과 현재 단계가 초기화되지 않습니다.
- 작은 화면에서는 종이 장식보다 질문과 입력을 먼저 보이게 합니다.

## 모션

| 요소 | 시간 | 역할 |
| --- | ---: | --- |
| 선택 상태 | 140~180ms | 체크와 메모 배경 반영 |
| 최종 노트 표시 | 180~300ms | 요약 화면이 나타남 |
| 화면 전환 | 360ms | 다음 페이지 이동 |
| CTA Hover | 140ms | 종이 그림자 변화 |

- 반복 회전과 무한 장식 모션은 사용하지 않습니다.
- `transform`과 `opacity`를 우선합니다.
- 모션 감소 설정에서는 모든 전환을 1ms 수준으로 줄입니다.
- 애니메이션이 없어도 선택과 진행 상태를 이해할 수 있어야 합니다.

## 접근성

- 각 질문은 `fieldset`과 `legend`로 묶습니다.
- 장면 전환 후 질문 H1으로 포커스를 이동합니다.
- 현재 단계는 텍스트 대체가 있는 진행률로 제공합니다.
- 카드의 시각적 입력을 숨겨도 실제 폼 입력은 유지합니다.
- 오류는 `role="alert"`와 `aria-live="polite"`로 전달합니다.
- 모든 터치 대상은 최소 44×44px을 유지합니다.
- 색상뿐 아니라 체크, 문장과 테두리로 상태를 구분합니다.
- 노트 가로줄과 테이프는 의미 없는 장식으로 처리합니다.

## 상태와 데이터 보관

- 생활 탐색 답변만 `sessionStorage`에 임시 저장합니다.
- 연락처와 개인정보는 React 메모리 상태에만 둡니다.
- 접수번호와 세션 ID는 화면 세션 동안 유지합니다.
- 질문 답변, 이름과 연락처를 URL에 넣지 않습니다.
- 제출 완료 시 임시 생활 답변을 삭제합니다.

데이터 코드와 Google Sheets 열은 [신청 폼 데이터 정의](신청-폼-데이터-정의.md)를 따릅니다.

## Google Sheets 연동

- 브라우저는 같은 출처의 Vercel API로만 전송합니다.
- Vercel API가 입력을 재검증하고 서버 비밀값을 추가합니다.
- 최종 신청은 `/api/daylog/application`으로 전송합니다.
- 개인정보 없는 퍼널 이벤트는 `/api/daylog/track`으로 전송합니다.
- 통합 Apps Script는 `daylog_life_session` 처리기로 라우팅합니다.
- 접수번호와 이벤트 ID로 중복 저장을 막습니다.

상세 구조는 [Google Sheets 연동 설계](신청-폼-Google-Sheets-연동.md)를 따릅니다.

## 성능

- 첫 화면에 사진, 영상과 외부 폰트를 추가하지 않습니다.
- 노트 줄, 테이프, 종이 겹침과 도장은 CSS로 구현합니다.
- 불필요한 모션 라이브러리를 설치하지 않습니다.
- 시각 상태 변경이 레이아웃 전체를 다시 계산하지 않게 합니다.
- 모바일에서도 선택 반응이 즉시 보여야 합니다.

## 분석 이벤트

단계 코드는 LIFE NOTE 용어로 통일하며 완성 노트 확인에는 `life_note_viewed`를 사용합니다.

| 단계 코드 | UI 의미 |
| --- | --- |
| `started` | 하루 노트 쓰기 시작 |
| `daily_rhythm_selected` | 오늘의 리듬 기록 |
| `energy_selected` | 두 시간 기록 |
| `past_pattern_selected` | 지속 방식 기록 |
| `change_area_selected` | 변화 영역 기록 |
| `together_style_selected` | 함께하는 방식 기록 |
| `life_note_viewed` | 완성된 하루 노트 확인 |
| `application_started` | 연락 신청 시작 |
