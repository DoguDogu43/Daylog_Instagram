# 데이로그 홈페이지 구현 명세

## 문서 목적

[홈페이지 디자인](../04-디자인/홈페이지-디자인.md)을 실제 웹사이트로 구현하기 위한 개발 기준입니다. 기술 스택에 종속되지 않는 요구사항을 우선 정의합니다.

실제 구현은 `/Users/won-young/Documents/ChatGPT/데이로그`에서 수행합니다.

## 확정 기술 스택

- UI는 React로 구현합니다.
- 언어는 TypeScript 엄격 모드를 사용합니다.
- 운영 배포는 Vercel을 사용합니다.
- 신청·퍼널 API는 Vercel Serverless Function으로 구현하고 React 브라우저와 동일한 출처로 제공합니다.
- Next.js, Vite와 라우터 선택은 기존 구현 프로젝트를 확인한 후 확정합니다.

## 현재 범위

초기 버전은 브랜드와 Life Session을 소개하는 반응형 마케팅 홈페이지를 기준으로 합니다.

### 포함

- 브랜드와 서비스 소개
- 데이로그의 차별점
- 서비스 흐름
- Life Interview 소개
- 코치 역할
- 60분 Life Session 소개
- 오프라인 공간 소개
- 예약 또는 신청 CTA 연결
- 모바일, 태블릿과 데스크톱 대응
- 기본 SEO, 접근성과 성능 최적화

### 별도 결정 필요

- 예약 기능을 사이트 내부에 구현할지 외부 서비스로 연결할지
- 고객 계정과 로그인 기능
- 결제 기능
- 콘텐츠 관리 도구
- 블로그 또는 매거진
- 다국어 지원
- 후기와 사례 관리

## 구현 전 필수 결정

1. React 빌드 도구, 라우터와 프로젝트 구조
2. `마룬이`의 역할과 공식 표기
3. 로고와 남녀 마룬이 원본
4. Hero 최종 문구와 CTA
5. CTA가 연결될 예약 방식 또는 URL
6. Life Session의 가격, 장소와 운영 시간
7. 문의, 사업자와 개인정보 처리 정보

자세한 목록은 [에셋 요구사항](../04-디자인/에셋-요구사항.md)을 참고합니다.

## 콘텐츠 구현 원칙

- 문구를 여러 컴포넌트에 중복해서 직접 입력하지 않습니다.
- 반복되는 단계, 질문과 일정은 구조화된 데이터로 관리합니다.
- 확정되지 않은 가격, 장소와 CTA 주소를 임의로 공개하지 않습니다.
- 서비스 세부 내용은 문서 원본과 의미가 달라지지 않게 합니다.
- `Life Session`과 `Life Interview`를 같은 서비스로 혼동하지 않습니다.

## Hero 구현

- 가장 중요한 H1은 페이지에 하나만 둡니다.
- 마룬이 비주얼은 콘텐츠를 가리는 배경 이미지보다 독립된 이미지 요소를 우선합니다.
- 이미지에 의미가 있으면 적절한 대체 텍스트를 제공합니다.
- 장식용 밑줄은 CSS 또는 별도 SVG로 구현하고 스크린 리더에 노출하지 않습니다.
- 텍스트와 이미지의 읽기 순서는 DOM에서 텍스트가 먼저 오게 합니다.
- 모바일에서는 중요한 얼굴과 자세가 잘리지 않도록 별도 크롭 또는 `object-position`을 지정합니다.

## 내비게이션

- 모든 메뉴는 실제 섹션 또는 페이지와 연결합니다.
- 키보드로 메뉴를 열고 닫고 이동할 수 있어야 합니다.
- 모바일 메뉴가 열리면 포커스 이동과 배경 스크롤을 관리합니다.
- 현재 위치 표시가 색상에만 의존하지 않게 합니다.
- `Escape` 키로 모바일 메뉴를 닫을 수 있게 합니다.

## CTA와 예약 연결

- Primary CTA는 한 화면에서 한 가지 주 행동으로 유지합니다.
- 버튼 문구와 실제 동작이 일치해야 합니다.
- 외부 예약 페이지로 이동하면 새 창 여부와 이동 사실을 명확히 합니다.
- 예약 링크가 준비되지 않은 동안 비활성 버튼을 공개하지 않습니다.
- 폼을 구현할 경우 성공, 오류, 로딩과 중복 제출 상태를 제공합니다.

## 반응형 기준

| 크기 클래스 | 너비 | 기본 동작 |
| --- | --- | --- |
| Compact | 0~599px | 1열, 세로 흐름, 간결한 상단 메뉴 |
| Medium | 600~839px | 1·2열 혼합, 태블릿 터치 밀도 유지 |
| Expanded | 840~1279px | 2열 중심, 태블릿을 PC처럼 축소하지 않음 |
| Desktop | 1280px 이상 | PC 내비게이션, 넓은 컨테이너, 좌우 Hero |

대표 설계 프레임은 `390 × 844`, `820 × 1180`, `1440 × 900`입니다. 최소 모바일 `320 × 568`, 태블릿 가로 `1180 × 820`, 낮은 PC `1280 × 720`도 필수 검수합니다.

프로젝트의 실제 콘텐츠와 기기 테스트 결과에 따라 breakpoint를 조정할 수 있습니다. 특정 기기명이 아니라 레이아웃이 깨지는 지점을 기준으로 결정하며, 상세 기준은 [반응형·모션 구현 기준](반응형-모션-구현-기준.md)을 따릅니다.

### 높이와 창 변화

- 첫 화면은 `100vh`보다 `100dvh`를 우선하고 필요하면 `100svh`를 함께 검토합니다.
- 노치와 홈 인디케이터를 위해 `env(safe-area-inset-*)`를 반영합니다.
- 높이 `480px` 미만의 가로 모바일에서 고정 헤더와 고정 하단 CTA를 동시에 유지하지 않습니다.
- 회전, 분할 창과 폴더블 접기·펼치기 후에도 현재 스크롤과 열린 메뉴 상태를 안전하게 정리합니다.

## 접근성 요구사항

- 페이지 언어를 한국어로 지정합니다.
- 제목 단계가 건너뛰지 않게 합니다.
- 모든 기능을 키보드로 사용할 수 있어야 합니다.
- 포커스 표시를 제거하지 않습니다.
- CTA의 최소 터치 영역을 44×44px 이상으로 합니다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공합니다.
- 인물과 공간 이미지에 의미에 맞는 대체 텍스트를 제공합니다.
- 장식 이미지는 빈 대체 텍스트로 제외합니다.
- 색상만으로 단계나 상태를 구분하지 않습니다.
- `prefers-reduced-motion`에서 불필요한 모션을 제거합니다.
- 본문 텍스트와 배경은 WCAG AA 이상의 대비를 유지합니다.

## 컬러 구현 주의

- Growth Yellow와 Warm Ivory는 대비가 낮으므로 노란색 글자를 아이보리 위에 사용하지 않습니다.
- 아이보리 배경의 노란 하이라이트에는 Deep Navy 또는 Charcoal 텍스트를 올립니다.
- Sage Green 배경에는 Clean White 일반 텍스트를 사용하지 않습니다.
- Primary 버튼은 Growth Yellow 배경과 Deep Navy 텍스트로 구성합니다.

## 이미지 요구사항

- 로고는 SVG를 우선합니다.
- Hero는 화면 크기에 맞는 `srcset` 또는 반응형 이미지 기능을 사용합니다.
- 사진과 래스터 일러스트는 AVIF 또는 WebP를 우선하고 적절한 fallback을 제공합니다.
- Hero 핵심 이미지만 우선 로드하고 화면 아래 이미지는 지연 로드합니다.
- 이미지에 명시적인 너비와 높이 또는 종횡비를 지정해 레이아웃 이동을 방지합니다.
- 인쇄용 고해상도 파일을 웹에 그대로 제공하지 않습니다.

## 성능 목표

- Hero 이미지와 글꼴이 초기 렌더링을 과도하게 지연시키지 않게 합니다.
- 사용하지 않는 자바스크립트와 애니메이션 라이브러리를 추가하지 않습니다.
- 외부 서체를 사용할 경우 필요한 굵기만 제공하고 표시 전략을 설정합니다.
- 초기 공개 전 실제 모바일 환경에서 Core Web Vitals를 확인합니다.
- 분석 스크립트와 외부 위젯은 필요한 경우에만 추가합니다.

## 홈페이지 모션

- 섹션 등장은 기본 `opacity` 변화와 최대 `12px` 이동으로 제한합니다.
- 진입 모션은 `240~420ms`, 카드 스태거는 `60ms`, 누적 지연은 `600ms` 이하로 유지합니다.
- 자동 반복, 큰 패럴랙스와 CTA 반복 튀김은 사용하지 않습니다.
- 스크롤 진입은 최초 1회 실행을 기본으로 하고, 섹션의 `30%`가 보일 때를 초기 임계값으로 사용합니다.
- 모션은 스크롤과 클릭에 중단 가능해야 하며 컴포넌트 언마운트 시 이벤트·타이머·관찰자를 정리합니다.
- `prefers-reduced-motion: reduce`에서 이동과 스태거를 제거하고 정지 완료 상태 또는 `100~180ms` 페이드로 대체합니다.
- 프레임마다 레이아웃을 유발하는 속성보다 `transform`과 `opacity`를 우선합니다.

## SEO와 공유 정보

- 페이지별 고유한 제목과 설명을 설정합니다.
- 회사명, 서비스명과 지역 정보가 확정되면 구조화된 정보에 반영합니다.
- Open Graph 제목, 설명과 대표 이미지를 제공합니다.
- 공유 이미지는 중요한 텍스트와 얼굴이 안전 영역 안에 있도록 제작합니다.
- 실제 공개 주소가 정해지면 canonical URL과 사이트맵을 설정합니다.

## 개인정보와 폼

- 신청 폼에서 필요한 정보만 수집합니다.
- 수집 목적, 보관 기간과 동의 내용을 제출 전에 알립니다.
- 민감한 생활 정보를 공개 웹 폼에서 과도하게 수집하지 않습니다.
- 상세한 Life Interview는 공개 신청 폼이 아니라 안전한 대화 과정에서 진행합니다.
- 외부 예약 도구를 사용할 경우 개인정보 처리 주체와 이동 사실을 안내합니다.

## 분석 이벤트 제안

분석 도구 사용 여부와 개인정보 정책을 확정한 뒤 적용합니다.

| 이벤트 | 의미 |
| --- | --- |
| `cta_click_hero` | Hero CTA 선택 |
| `cta_click_session` | Life Session 신청 선택 |
| `process_view` | 서비스 흐름 섹션 확인 |
| `booking_start` | 예약 과정 시작 |
| `booking_complete` | 예약 완료 |

이벤트 이름은 실제 분석 도구 규칙에 맞게 조정합니다.

## 완료 기준

- 디자인 문서의 컬러와 콘텐츠 계층이 구현되어 있습니다.
- 모바일, 태블릿과 데스크톱에서 콘텐츠가 잘리거나 겹치지 않습니다.
- CTA가 올바른 위치로 이동하고 키보드로 사용할 수 있습니다.
- 모든 필수 이미지가 최적화되고 대체 텍스트가 적용되어 있습니다.
- 색상 대비와 포커스 상태가 접근성 기준을 충족합니다.
- 임시 문구, 빈 링크와 미확정 운영 정보가 공개 화면에 남아 있지 않습니다.
- 실제 모바일 네트워크 환경에서 초기 화면의 성능을 확인했습니다.
- 예약 또는 문의 흐름을 처음부터 끝까지 테스트했습니다.
